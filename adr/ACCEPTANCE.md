# 验收、安全测试与发布门槛

## 移动与双云增量门槛

本轮按 [ADR-0002](0002-mobile-credentials.md)、[ADR-0003](0003-cloud-sync.md)、[ADR-0004](0004-kdbx-advanced-passkeys.md) 细化既有标准，实施证据对应M01–M24；以下均待原生/协议实测。

| 范围 | 新增阻断案例 |
| --- | --- |
| iOS | 主程序终止时扩展读/写；KDF+附件+历史峰值；有权限但只读；索引过期；多进程撤权与提交竞态 |
| Android | begin与最终请求不同；PendingIntent复选/取消；错误包签名/DAL；合法ROR不被错误同域规则拒绝；clear-state不误删库 |
| OneDrive | 精确scope与账号/端点不兼容；A会话开始→B提交→A完成；预授权URL泄漏；202误标提交；旧generation成功误消除新待同步 |
| WebDAV | 服务宣称支持却忽略版本条件；弱ETag；HTML登录页；跨源认证头泄漏；缺失CAS时无条件覆盖 |
| Passkey | KPEX旧别名/编码、同ID不同key、多个账户相互覆盖、只有硬件alias、未持久化先回成功、系统索引包含私钥 |
| 附件 | 删除当前引用毁坏历史、流顺序改变损坏Protected值、明文预览残留、自动拆库或降低KDF规避内存限制 |

来源验证区分WebAuthn client与平台provider职责；不得把origin字符串与RP ID完全相等作为统一规则。新平台增强（OTP、条件升级、Credential Exchange）没有真机/对端证据就不计为已支持。

日期：2026-10-12。下列均为**待实施验收标准**，不是已经通过的测试。仅用合成数据；真实密码库不进入 CI、日志、浏览器截图或 agent 对话。

## AC-KDBX：无损兼容是写入前提

测试组合覆盖 KDBX3.1/4.0/4.1、AES/ChaCha20、AES-KDF/Argon2d/Argon2id（按格式适用性）、主密码/密钥文件/组合密钥、Unicode/空字段/长字符串。

往返步骤：参考客户端创建 → keex 读取 → 只改指定字段 → keex 保存 → 参考客户端读取并编辑 → keex 再读取。对比语义而非文件字节；历史/UUID/时间/DeletedObjects/组嵌套/自定义图标/标签/字段引用/自定义字段/保护标记/二进制附件内容和引用都要覆盖。KeePass、KeePassXC、KeeAgent、目标移动客户端分别记录版本和适用范围。

未知受保护字段必须参与正确的内层流解码与重编码；改变条目顺序、增删保护字段、历史含保护字段时仍可重开。第三方 Passkey/KeeAgent 数据既要验证保留，也要验证实际签名/登录，两者不能互相替代。

错误案例：错误凭据、缺失密钥文件、KDBX 4.x 头部/块HMAC破坏、KDBX 3.1 缺失或不符的 `HeaderHash`（3.1 没有 HMAC，必须只读，见 [THREAT_MODEL.md](THREAT_MODEL.md) T1）、截断、尾部污染、超大KDF参数、压缩炸弹、XML深度/实体攻击、不支持算法/版本。拒绝或只读后不写回；正常日志不得暴露密钥材料。任一静默丢字段问题阻断 G0/G1。

## AC-SAVE：事务、崩溃与恢复

在生成密文、写临时文件、刷新、校验、替换、备份轮转、更新版本记录每一步注入终止/满盘/权限撤销。重开后至少保留旧完整库或新完整库，不能出现“成功保存”但文件不可解密。

验证本地普通文件、macOS授权文件、Android文档provider、iOS文件provider的实际替换能力。复制/重命名不等于所有provider原子提交。多进程同时写时必须版本冲突或排队；不允许最后一个写进程无条件胜出。

备份恢复覆盖设备丢失、主密码变更、密钥文件缺失、旧版本库、损坏最新快照和祖先丢失。备份加密但不意味着旧密钥失效，文档必须解释。

## AC-SECRET：密钥、会话与隐私

逐项验证手动锁库、系统锁屏、休眠、闲置超时、切库、应用进入后台、设备保护权限撤销。锁后新/旧句柄的读取、复制、填充和签名均拒绝；取消解锁/KDF/系统认证不能复活旧会话。

扫描日志、错误上报、Dart状态恢复、系统任务预览、剪贴板历史提示、临时文件、导出目录、搜索索引和浏览器存储。默认不得有主密码、完整卡号/证件号、OTP seed、恢复码或私钥。显示秘密造成的框架/OS内存副本列为残余风险，不能宣传完全内存擦除。

剪贴板仅在本次值/可验证所有权仍一致时清除，不清用户后来复制内容。受平台限制无法核对时采取保守策略并说明。恢复码、照片、Passkey明文导出要单独确认；生成器历史默认不持久化。

生物/设备解锁测试错误识别、取消、重新录入、锁定、迁移备份、设备时间变化。快速解锁材料不能独立用短 PIN 离线暴力破解；无法建立足够设备保护时不启用。

威胁模型（[THREAT_MODEL.md](THREAT_MODEL.md) T4/T5）必须说明：不保证防住已控制 OS/内核的攻击者；仅 socket 文件权限也不等于隔离同 UID 的所有恶意进程；需要按次授权等额外限制而非绝对安全承诺。

## AC-SYNC：并发、恶意远端与离线

覆盖：A/B 离线修改不同条目、同字段、同条目不同字段、删除对编辑、组移动、附件增删、历史恢复、HOTP取码、Passkey注册。无冲突自动合并，有冲突保留双方并要求明确选择；数据不因时间戳高低被静默丢弃。

远端情形：ETag变化、412、弱ETag、错误/缺失条件写支持、401/403、跨源重定向、TLS异常、429、响应截断、上传成功但客户端超时、重复请求、旧密文回放、磁盘满。未建立可信本地版本基线的新设备不能被承诺检测所有远端回滚。

锁库中只传输密文，显示“等待解锁合并”；网络恢复不擅自解密。同步令牌撤销不影响本地开库；改变库密钥后旧设备不能覆盖新库。除必要同步provider外默认无外联。

## AC-SSH：真实代理与授权

macOS/Linux用真实`ssh`、`ssh-add`、Git；Windows用目标OpenSSH组合验证。测试端口/管道占用、已有系统代理、旧socket、进程退出、其他用户访问、标准权限安装与升级。

测试每密钥加入/移除、按次确认/拒绝/超时、期限到期、锁库与签名并发、请求长度异常、未知签名算法、代理转发。授权公钥与未授权公钥隔离；私钥/签名输入不进入日志和磁盘。

只有验证 OpenSSH 会话绑定/目的地约束后才可声称限制远端目标。外部代理模式如未来上线，必须另行提示“私钥已交给外部进程，keex 无法保证其清除”，不能沿用自有代理验收结论。

## AC-CREDENTIAL：自动填充、OTP 与 Passkey

OTP按 RFC6238/4226固定向量覆盖算法/位数/周期/时间边界/HOTP计数。二维码本地解析，导入错误不会覆盖原seed；时钟异常给出解释。

自动填充覆盖合法站点与同形域名/子域/iframe、应用签名变化、未授权调用方、导航切换、已关闭库、主app已退出、重复请求、取消/超时。不能仅匹配可由攻击者声明的站点标题或包名字符串。

Passkey分别验收“存储保留”“创建”“认证”“跨客户端互通”，标识不能混用。验证RP ID、origin/可信调用者、challenge、防重放、userHandle、credentialId、算法、用户存在/验证标志、同步凭据备份/计数策略。先持久化再返回注册成功；失败可恢复且不制造无法使用的孤立凭据。

Android14+ provider和旧版Autofill独立；Apple原生扩展真机核对entitlement和API版本。扩展冷启动、系统杀进程、内存上限、多库、主应用并发写入必须测试。浏览器扩展与桌面bridge配对、消息格式、来源认证也需独立测试。

## AC-UX：中文与跨平台

五项导航固定，窄屏底栏与宽屏侧栏同序；生成器/安全检查不变为第六tab。空状态/错误/只读/不支持/未配置/等待解锁文案完备。账户密码不叫主密码；同步未确认不叫已同步。

宽度320/390/768/1440、深浅主题、字体放大200%、键盘/读屏、中文长文件名与混合用户数据。秘密不自动播报；验证码变化不每秒轰炸读屏。触控最小尺寸、焦点环、对比度、底部安全区与软键盘遮挡单独核对。

## AC-PERF：先记录基线，再固定预算

基线集合：1,000与10,000条目，含历史和合成附件；Android中档机、Apple扩展真机、Apple Silicon桌面、Windows标准用户机与Linux桌面分别记录机型/OS/构建模式。

初始目标（待P0实测调整并记录原因）：已解锁摘要搜索p95≤100ms；列表滚动不反复解密全库；主界面首个可交互帧p95≤1.5s（不含用户认证和KDF）；KDF按安全基线校准到可接受时间，不硬以低延迟为唯一目标。扩展峰值内存必须留出OS限额余量，不硬写统一上限；大附件操作可取消、不阻塞UI。

基准必须区分冷/热启动、debug/release和模拟器/真机。未跑不标绿；性能不过关不能靠关闭认证或降低既有库KDF规避。

## 发布判定

阻断项：数据丢失、无损门槛失败、锁库后越权读取/签名、填充给错误来源、KDBX校验绕过、同步静默覆盖、真实秘密外传、未解决高危安全缺陷。平台未测或功能缺失写进支持矩阵，不能给五端统一绿色标签。

证据包含固定依赖、合成样本、命令、日志脱敏、截图、缺陷及修复复测。最终由独立审查者核对 G0–G5，不用“生成了文档/页面可打开/编译成功”代替产品验收。
