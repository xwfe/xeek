# ADR-0006：从密码管理器扩展为个人数据保险柜

日期：2026-10-16。状态：**产品方向按用户本轮要求纳入规划；字段编码、安全增量与生产实现仍待实验和独立复核**。

## 1. 决定

`keex` 的产品定位调整为：**中文优先、本地优先、以 KDBX 为基础的个人数据保险柜，统一管理凭据、身份资料、金融账户、卡片、通信资料及其维护事项。** 密码管理是安全基础，不被弱化为普通备注功能。

在现有项目内扩展，不另建出海卡包产品、不另造主数据库或密码算法。用户本轮重申 Web + 移动端需求：Android/iOS 保留原计划，Web 进入明确的当前实施路线，但使用独立安全门槛，见 [ADR-0007](0007-web-vault-client.md)。2026-11-21 按 [ADR-0008](0008-nsh-unified-clients.md) 纳入 macOS/Windows 资料客户端，以 NSH + TSX 和共享 Rust 为目标；Linux 与桌面增强仍为后续；Web 不等于桌面应用，微信小程序也不随之获批。

“个人数据保险柜”是产品概念；具体 `.kdbx` 文件仍称“密码库”，解锁密钥仍称“主密码”。不机械替换既有协议术语。

## 2. 为什么并入，而不是另起项目

新增对象与现有 K017/K024/K028/K029/K030/K034–K041 高度共享：类型投影、受保护字段、附件、导入、锁库、同步、备份和恢复都已经在规划中。另开产品会重复承担最难的安全工作，并让同一账户、号码和凭据再次分散。

但当前仓库**没有生产客户端或安全核心**。这不是给成熟密码管理器加几个表单，而是在正式实现前扩充领域边界。应先把新增字段与关系加入兼容性样本，再实施 writer；不能借新定位跳过尚处 REVIEW 的 K001/K002。

KDBX 官方规范允许扩展数据和附件，适合低频修改的个人资料；格式可扩展不等于任意库或第三方客户端都能无损写回。`keepass-rs` 的 4.1 写入仍被上游标为实验性；本仓库 K002 也记录了参考客户端对部分语义的改写，不能只以“另一个客户端能打开”为通过标准。依据见 [研究 PV01–PV03](research/personal-vault-2026-10-16.md)。

## 3. 范围

| 层次 | 本次纳入 | 不随之纳入 |
| --- | --- | --- |
| 安全基础 | 密码、OTP、恢复码、Passkey、KeeAgent 数据、解锁、备份与密文同步 | 自建加密格式、弱化主密码、跳过系统凭据验证 |
| 资料类型 | 金融账户、实体/虚拟卡、号码、SIM/eSIM 配置、套餐、证件、重要文档、会员/礼品卡、订阅资料 | 完整记账、银行聚合、资产估值、投资建议、网盘或档案馆 |
| 资料关系 | 卡归属账户、订阅付款方式、号码绑定服务、证件用于验证、替换与历史 | 自动根据同名推断身份、复制整份秘密到每个对象 |
| 生命周期 | 到期、续费、保号、资料更新、换卡/停号处理清单 | 自动转账、充值、注销、登录银行抓取、直接安装或切换 eSIM |
| 客户端 | Android/iOS/macOS/Windows；独立验收的 Web 客户端 | Linux、通用浏览器扩展、微信小程序及桌面 SSH/自动输入/CLI 增强 |

“线上财务”在首版解释为金融服务的账户与资料管理，而不是账务系统。余额只允许带币种、来源、记录时间的手工快照；到期规则和套餐限制是用户维护的信息，不冒充银行或运营商实时状态。

不引入公共卡片推荐社区、联网图标聚合、自动上传证件 OCR、大模型读全库或第三方可执行插件。模板先做内置声明式 schema；未来新增上述能力必须另作隐私、权限和容量决策。

## 4. 信息架构：保持五导航，新增二级领域

保留“密码、验证、证件、银行、设置”及同序宽屏侧栏。不增第六个 tab，也不擅自改名为“全部、资产”等新体系。

| 入口 | 领域与说明 |
| --- | --- |
| 密码 | 登录、服务账户、安全备注；登录记录可关联银行账户、订阅和验证资料 |
| 验证 | OTP、Passkey、恢复码；新增“号码与套餐”二级分类，容纳号码/SIM/eSIM，但不把它们标为可签名凭据 |
| 证件 | 证件、地址证明、重要文档、会员/礼品卡等资料模板 |
| 银行 | 银行/线上金融账户、实体/虚拟卡、订阅与付款关系、手工金额快照 |
| 设置 | 库、安全、同步、备份、通知与能力状态；不成为资料堆放区 |

“全部资料”和“待办”是全局搜索/工具栏入口、筛选视图，不是一级导航。某条资料跨视图出现仍只有一个 Entry UUID，不复制存储。具体筛选、详情和流程见 [规格](PERSONAL_VAULT_SPEC.md)。本轮不修改 HTML 原稿或声称已实现新界面。

## 5. 架构取舍

保持单一权威数据：业务字段、关系、规则、完成记录、附件全部进入加密 KDBX；解锁后生成搜索与反向关系索引，锁库撤销。OS 通知调度仅持有用户同意的最小调度信息；Web 缓存只允许密文且需要显式启用。没有并行的明文 SQL/JSON 业务主库。

新增的是 `records / relations / lifecycle / templates` 领域模块，先按模块放在共享 Rust 核心和 NSH/TSX 主 UI 内，具体生产目录在 K010 定版。不要预先拆成服务、额外进程或十几个 crate。底层存储接口继续负责事务和版本检查；业务模块不能绕过 `VaultSession` 直接写 XML 或云端文件。

KDBX 以整库读写为主，本项目不承诺海量附件、持续交易流水或高并发协作。大库影响移动凭据扩展内存预算；达到容量阈值应提示、拒绝新增或降为只读，而不是静默拆库、删附件、降低 KDF。阈值由 K069/K070/K024 实验确定。

统一存储也意味着集中风险。将整库交给浏览器解锁后，“网页只展示某类字段”不是密码学隔离。首版不宣称 Web 能安全地只解锁主库的一小部分；未来真的需要隔离，应由用户明确建立独立 KDBX，另写同步/迁移方案。

## 6. 对现有任务的影响

现有 K001–K067 编号与 M01–M24 从属关系保留。K017/K028/K029 等增加领域验收，不重新建一个竞争的任务系统。新增主任务 **K068–K089**，唯一状态源仍为 [TASKS.md](TASKS.md)，阶段与交接见 [专项实施计划](PERSONAL_VAULT_PLAN.md)。

K066 只保留微信小程序的后续受限入口研究；Web 由 ADR-0007 和新增任务承接。移动基础版与 Web 可以分开验收，各端可以分批发布；当前完整跨端版还需 ADR-0008 的 GN、桌面 K095/K096 与 K089，不能只完成移动或 Web 就标整体完成。

## 7. 决策不等于验证

本次批准的是“在 keex 内按该方向规划”。具体编码由 K068/K069 固定；Web 共享运行时、文件事务、浏览器兼容性与双云授权分别由 K070–K072 实测。失败时记录 BLOCKED、反例和候选修复，不将弱化安全作为默认降级。

2026-10-16 方案轮未安装工具链、未使用真实库、未连接金融/运营商/云账户，未提交或推送代码；该句是当轮记录，后续操作按当前授权与项目约定执行。研究只提供来源与可借鉴点，不构成对社区产品的安全审计或生产库选型批准。
