# 个人数据保险柜：领域、交互与数据契约

日期：2026-10-16，编码细化：2026-10-18。状态：**领域实施规格；K068 已形成可执行合成契约，生产实现和安全/兼容门槛尚未通过**。产品范围见 [ADR-0006](0006-personal-data-vault.md)；Web 差异见 [ADR-0007](0007-web-vault-client.md)；实施顺序见 [专项计划](PERSONAL_VAULT_PLAN.md)。

## 1. 对象不是页面，也不是所有东西都叫卡

沿用 KDBX 标准 Entry UUID，类型决定字段与视图，不改变组归属。字段拼写、值域、保护及关系方向以 [K068 字段契约](K068_FIELD_CONTRACT.md) 和其中链接的可执行字典为准；以下为领域说明，不是已存在的生产 API。

| 类型 | 最小业务字段 | 关联与重要约束 |
| --- | --- | --- |
| 登录/服务账户 | 服务、用户名、登录地址、凭据引用、注册地区、用途 | 保留既有密码/OTP/Passkey 模型；有账号不代表已验证身份 |
| 金融账户 | 机构、持有人、账户标识、账户类型、币种集合、开户地区、资料状态 | 银行/支付平台等以模板区分；一个账户可有多张卡、多币种，不按一张卡复制账户 |
| 支付卡 | 实体/虚拟、所属账户、持卡人、卡组织、号码、到期月份、账单地址、手工限额/费用 | CVV/PIN 可不存且默认保护；无支付执行能力；旧卡保留替换关系 |
| 通信线路/号码 | 可选号码、运营商账户、号码归属地区、用途、状态、核实时间 | 号码与运营商账户分开；号码可能变更，不能拿号码字符串作为永久 ID |
| SIM/eSIM 配置 | 物理/eSIM、可选 ICCID/EID/安装设备说明、可选线路及激活资料 | 尚未安装的配置可以没有号码、ICCID、EID 或线路；别名与类型即可保存，身份仍用 UUID；换配置不覆盖旧资料 |
| 通信套餐 | 供应商、覆盖地区、流量/语音/SMS 描述、激活规则、起止/周期、价格、核实时间 | 可关联线路或配置；支持尚未安装的套餐；“支持短信/验证用途”为未知/用户核实，不默认真 |
| 订阅 | 关联服务、套餐、金额+币种、计费周期、下次日期、付款关系、取消说明 | 和服务登录、付款卡分别存储；试用、扣费、自动续费意向、用户确认取消分别表示 |
| 证件/文档/其他卡券 | 证件或文档类型、标识、签发/有效日期、附件；卡券可有条码和手工余额 | 无法律效力或付款能力承诺；附件引用沿用标准 KDBX；不是通用云盘 |
| 维护事项 | 所属资料、规则、截止语义、状态、完成记录、可选证明引用 | 存规则和用户记录，不能把通知已送达当作事项已完成 |

保留安全备注/自定义模板作为长尾入口，但不要求用户为所有类型手写字段。模板必须声明字段类型、保护策略、校验器、显示顺序和适用操作；模板不是可执行插件，不运行脚本或自动联网。

## 2. 字段、安全级别和事实来源

所有个人字段均受密码库整体加密，包括名称、地区、用途、关系和日期。字段可再分“摘要可显示”和“需显式揭示”：后者包含完整卡号、账号、电话、证件号、激活资料、PIN/PUK、密码、OTP、恢复码和私钥。摘要也不能放进日志、URL、系统搜索或第三方分析。

默认列表显示别名、类型、用户选择的脱敏末位、资料状态和是否有待办。不要为渲染列表解出全库秘密；号码末位也属于隐私，只在解锁后的视图使用。逐字段显示/复制要做用途与 epoch 检查；“显示卡号”不等于同时显示 CVV、PIN 或二维码。

金额按 K068 使用严格十进制字符串和明确币种，禁止浮点中转或累计；未知币种/精度保留只读。余额、剩余流量、限额的值与 `recordedAt / source / confidence` 整体原子化，不能把新金额和另一版本的核实依据拼接；订阅价格与计费周期也整体保存。没有外部接口时只能显示“手工记录”，不能显示“实时余额”。不自动汇总不同币种或推断资产净值。

日期类型区分：`DateOnly`（到期日）、`YearMonth`（卡片到期月份）、`Instant`（完成时间）、带 IANA 时区的本地计划时间。不同语义不统一成 UTC 午夜。只有月份的卡片有效期保留月份精度；提醒可按约定在月末前触发，但不声称银行在该时间一定停卡。

地区至少按需要区分：注册地、开户/发卡地、账单地址、号码归属地、套餐覆盖地、用户所在地；不能合并成一个“国家”。不根据发卡地自动得出支付可用性，不根据 eSIM 覆盖地自动得出 IP 出口地区。

来源采用用户录入、手工核实、导入文件、将来经批准的官方接口等受控枚举；保留核实日期。保存来源网页只作为加密引用，不自动访问或抓取。界面区分“用户标记已停用”和“机构确认已停用”。

## 3. KDBX 映射与兼容

### 3.1 存储原则

标准字段 Title/UserName/Password/URL/Notes、UUID、组、标签、时间、历史、附件继续按生态语义保留。业务字段优先使用可读的、有命名空间的自定义 String 字段；秘密标记 Protected。少量 schema 元数据放加密 XML 的 CustomData，**不放 PublicCustomData**。KDBX 的 Protected 是内层/内存保护机制，不是字段级访问控制或另一把密钥。[PV01]

命名空间、完整字段字典和单组 JSON 编码已在 K068 固定；各端不得自行命名或将合成校验结果视为生产写入许可。简单可编辑资料不压成唯一大 JSON；必要的复合值按原子组编码并保留未知子字段。不得仅依赖 CustomData 的修改时间判定新旧——现有 K002 已发现参考客户端会改写部分时间语义。

维护事项是标准 KDBX 条目的一种类型，用稳定 UUID 关联所属资料；外部客户端仍可见标题与必要说明，但不会自动执行其规则。数量必须计入库容量/性能预算。运行时索引和 OS 通知表不成为新的权威记录。

### 3.2 版本、迁移与外部编辑

每个 keex 类型带 schema 版本；无 marker 的旧条目按既有普通条目展示，类型识别不自动写回。升级流程：预览 → 加密备份 → 明确确认 → 同一保存事务 → 再读验证。失败不删除原字段；降级客户端遇到无法保留的新类型应只读，而不是重建成五字段。

导入/克隆新建 UUID；同库复制不能复用原身份。复制库不自动断言两个文件属于同一实时同步绑定。库定位继续使用本机 VaultBindingId，不编造一个所有 KeePass 客户端共有的官方库 UUID。

既有 Passkey 的 `keex.parentEntryUuid` 是兼容别名；关系适配层可读取，但在 K069 验证与显式迁移前不删除或悄悄改写。它与新 credentialOf 父关系冲突时保留双方、只读待复核。已有“登录密码+KPEX”混合条目保持原 UUID；新建多个 Passkey 仍各有独立标准条目，不把不同私钥压成一条记录，也不因分类拆分旧凭据。

### 3.3 兼容性验收

沿用独立语义比较器与多来源样本。先补齐 K002 未覆盖的 KDF/cipher/来源矩阵，再验证新增类型、未知 Protected 字段、链接、历史、二进制引用、回收站和第三方改类型。对照客户端自身的变异必须单列，不能把变异后的输出重新定义成正确答案。

目标不是“所有客户端都有同样界面”，而是“普通客户端可读基本资料，未理解的数据可保留；keex 自己读改写不静默丢数据”。一端可读不代表可写，一端可保留 Passkey 不代表能签名。

## 4. 关系模型与边界

只在同一密码库内建立强关系；跨库首版只允许不带秘密的手工说明，不提供可自动解引用/级联写入的跨库 ID。

关系在来源条目中保存稳定 `relationId`、关系类型、目标 Entry UUID、有效状态和必要限定信息；反向索引解锁后计算，不另存第二份关系。底层采用 K068 按 relationId 分字段的编码。目标+类型+状态+作用期作为一个原子关系组；不同关系 ID 的新增也须检查来源/目标类型、方向与当前槽位基数。两个设备分别新增当前付款方式同样构成冲突；同一关系的改目标/删边必须显式解决。

| 关系 | 举例 | 禁止推论 |
| --- | --- | --- |
| belongsTo | 虚拟卡属于金融账户 | 不能推出该卡能操作账户所有余额 |
| paidBy | 订阅由某卡或账户付款 | 不能推出扣款成功或获得转账权限 |
| verifiedBy / recoveredBy | 服务使用某号码验证/找回 | 不能绕过原生来源校验；不能自动把该服务注册为同一 RP |
| usesProfile / usesPlan | 线路关联配置和套餐 | 不能推出配置已安装或套餐已激活 |
| documentedBy | 账户关联地址证明/证件 | 不能推出 KYC 已通过 |
| replaces | 新卡/新配置替代旧资料 | 不自动迁移历史扣费，也不删除旧对象 |

状态至少区分有效、历史、待复核。未知目标显示“关联资料缺失”，不自动寻找同名替代。图遍历有上限并防循环；首版用分组列表，不做关系图编辑器。

归档、业务停用、删除至回收站是不同动作。删除被引用资料先展示影响，可保留悬空引用用于恢复；绝不级联删除密码、Passkey、付款记录或附件。恢复沿用原 UUID；永久清除需二次授权并说明历史/备份不随之消失。

## 5. 三个首版闭环

### 换卡

打开旧卡 → 查看当前付款关系 → 创建/选择新卡 → 生成迁移清单 → 用户到服务商修改付款方式 → 回到 keex 逐项确认 → 确认时才更新对应关系，并保留旧关系历史。未处理事项仍引用旧卡；不能点击“已换卡”后批量假定所有扣费已迁移。

### 停号/更换 eSIM

查看线路的登录、验证和恢复依赖 → 标注高风险未处理项 → 用户到源服务处理 → 逐项确认。仅换 eSIM 配置但号码不变时，允许替换配置而保留线路及其账户关系；数据专用配置不制造假号码。保号规则依据最近一次用户确认的有效操作计算，点击提醒或点击充值链接不算完成。

### 证件/套餐/订阅到期

建立精度正确的日期和规则 → 在应用内显示截止日及依据 → 申请设备通知权限（可拒绝）→ 通用通知 → 解锁查看事项 → 手工记录已处理或延后。规则已过核实期限时提示“需要复核”，不自动认定用户已失去服务。

## 6. 规则与通知

规则最小集：一次性日期、按日历月/年重复、基于最近有效操作滚动、用户指定下一次日期。每个规则有 `ruleId`、版本、时区/精度、来源、核实时间、提前量、启停状态。完成事件有稳定 ID、发生时间、记录来源和可选证据引用；取消与撤销完成可追溯。

月末、闰年、夏令时、旅行换时区必须定义：月底月付按目标月最后一天截断后，下次仍由原始锚点计算，不能从 2 月 28 日永久漂移为每月 28 日；日期型提醒使用规则的时区，不跟设备旅行自动改业务截止日。欠缺时区/运营商规则时保留未知并要求用户设置，不猜测。

通知调度是从加密规则派生的本机缓存，仅含随机调度 ID、最小触发时间与通用文本，不含标题、机构、金额、号码、激活码、条目 UUID 或深链中的秘密。映射保留在受设备保护的位置；卸载/关闭通知/移除库/删规则须清理相应调度。单纯锁库不撤销已同意的通用通知，但通知不能解锁、取数或完成事项。

锁库不允许运行规则解密；只可由 OS 触发先前排好的通用通知。有限调度窗口、系统省电、通知权限、重启和后台限制必须在界面解释。跨设备可指定主提醒设备或全部设备，无法承诺离线状态下全局恰好一次。修改、恢复、同步后按规则版本对账，不凭通知 ID 当作业务状态。

Web 首版只保证打开且解锁时的待办计算；不做云端明文定时器，不承诺关闭网页后准时通知。移动端通知能力不能作为 Web 已实现的证据。

## 7. 交互约束

保留五导航；“验证 > 号码与套餐”“银行 > 账户/卡片/订阅”“证件 > 证件/文档/其他卡券”采用二级筛选。全局“全部资料”覆盖所有类型，提供类型、地区（注明含义）、状态、标签、是否临近到期的过滤。支持无号码 eSIM、未激活配置和未知字段的空状态。

详情采用“资料、关联、维护、历史/附件”分区；宽屏列表+详情、窄屏逐页进入，两端同一模型。新增时先选模板，可选字段不阻塞最小保存；对缺关键识别字段的记录显示不完整而不是伪造值。

搜索默认只索引解锁后的摘要；搜索完整号码等敏感值须显式选择且仅在当前会话执行。搜索词不进 URL、历史、遥测或持久化浏览器状态。批量操作先预览影响，每次提交带基线版本；中途锁库/文件改变后拒绝旧计划。

所有显示含义必须清楚：资料状态、服务状态（手工）、本机保存状态、同步状态、能力状态是五个维度，不用一个绿色“正常”混写。对未知类型、破损关联、权限不足、只读库和不支持的浏览器操作给出明确下一步。

## 8. 一致性与拟定接口

接口候选：`listRecords / readRecordView / applyRecordPatch / listRelations / planReplacement / commitMaintenanceChanges / listDueItems / recordCompletion / previewTypedImport`。所有调用沿用会话句柄、epoch、预期库 generation 和 Entry UUID；错误结果不返回敏感载荷。

替换计划是内存中的可取消草案，不是授权。执行前复核基线及所有受影响对象，单次事务成功才更新 UI。同步时日期+时区+精度、金额快照+来源/时间/可信程度、订阅价格+计费周期、套餐激活规则、同一关系组、同一完成事件均按业务原子组处理；不同组的三方合并也须通过最终业务约束，冲突保留双方和祖先。

本机回滚依赖加密快照，不以“逆向再写一次”假装事务回滚。架构不引入 CRDT、微服务或通用工作流引擎；当前离线个人资料规模先用明确的三方合并与受控状态机。

## 9. 规格完成不等于功能完成

上述类型、规则、接口、目录均是拟定契约。具体证据按 K068–K089 记录；新增字段必须过 AC-VAULT-DATA/REL/LIFE/COMPAT，Web 还需 AC-WEB。来源 PVxx 见 [研究记录](research/personal-vault-2026-10-16.md)。
