Rust 生成的 `.nsh/types/keex/vault.d.ts` 实际包含：

```ts
interface Ticket { binding: number; epoch: number; }
interface Summary { id: string; title: string; }
// VaultSession instance 的受限调用：
beginUnlock(): Ticket;
unlock(ticket: Ticket, password: string): Promise<Ticket>;
page(ticket: Ticket, query: string, offset: number, limit: number): Promise<Summary[]>;
readField(ticket: Ticket, entry: string, field: string): Promise<string>;
setUsername(ticket: Ticket, entry: string, value: string): Promise<void>;
saveCopy(ticket: Ticket, password: string): Promise<string>;
lock(): void;
```

分页上限 50，UI 当前每页 2 条；摘要只有 ID/标题，不传全库 JSON、字段全集、密钥或内部 Database。标题也属敏感 UI 内容，不持久化。字段按需单独读，唯一编辑接口沿用 UserName tracked 修改。参数再次由 Rust 检查；稳定脱敏码包含 UNLOCK_FAILED、FIELD_NOT_FOUND、INVALID_PAGE、LOCKED_OR_BUSY、STALE_SESSION、SAVE_FAILED/SAVE_IO、WORKER_FAILED。

解锁请求先同步 beginUnlock 提升 epoch，再异步启动；即使任务尚未调度时就锁库，也不能在锁库后重新安装会话。Rust 每个实例有独立 binding，已解锁操作取走 Vault 独占工作，busy 时拒绝并发调用，交还/返回前核对 binding/epoch；锁库清当前 Vault、提升 epoch，后台持有的旧 Vault 不能交还。TSX 额外用 uiEpoch 丢弃旧 UI 更新并清空字段/口令/摘要信号。Rust 单测显式覆盖 worker 持有 Vault 时 lock→accept 拒绝，TSX 覆盖排队解锁取消和旧句柄拒绝，不将二者混写成系统后台生命周期实测。

`nsh_core::blocking`（`crates/nsh-core/src/element/ambient.rs:1622–1642`）实际调用 spawn_blocking；本适配把 KDF/解析、分页扫描、字段访问、保存序列化及文件 IO 均放该路径，不以 async 关键字冒充后台调度。密码仅作为当次 String 输入，不保存在会话；保存时再次输入公开合成口令。masked 不是安全输入、JS 擦除或零副本保证。
