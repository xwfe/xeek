# K072 证据：浏览器 WebDAV 条件提交

日期：2026-10-31。状态 **DOING**，这里只有 WebDAV 部分，**OneDrive 没开始**（要专用测试账号）。依赖 K001 还在 REVIEW，这是合成预实验：只连本机测试服务器，只用合成数据和合成账号。代码和复现方法见 [tests/web_storage](../../tests/web_storage/README.md)。

## 结论先说

**浏览器里能做到安全的 WebDAV 条件提交，但只对实测通过的服务器成立；同样宣称支持 WebDAV，结果可以完全相反。**

| 服务器 | 能力探针 | 上传发一半断开 | 过期 If-Match（同一秒、同样大小） |
| --- | --- | --- | --- |
| Apache 2.4.67 mod_dav（macOS 自带） | 通过 | 还是旧版 | 0/6 被覆盖 |
| WsgiDAV 4.3.5 | **不通过**（ETag 不一定变） | **文件被截断成半截新内容** | **6/6 被覆盖** |

WsgiDAV 的 ETag 是“inode-修改时间到秒-大小”，它自己标成强校验器，所以同一秒内写同样大小的内容，版本号不变，If-Match 拦不住。它写文件时直接 `open(path, "wb")`，所以上传中断会毁掉原文件。

## 定下的规则

| 规则 | 依据 |
| --- | --- |
| 连接时先在临时对象上实测，没通过就不走自动覆盖，只写随机名字的冲突副本 | 上面这张表；用品牌或 OPTIONS 响应都判断不了 |
| 同样大小连写 3 次检查 ETag 是否都变 | 只写一次可能恰好跨秒，把 WsgiDAV 这类误判成安全 |
| 弱 ETag 等 1.1 秒再读一次，还是弱的才算不合格 | Apache 对 1 秒内改过的文件只给弱 ETag，之后变强；不处理的话刚写完的文件永远提交不了 |
| 请求不带 cookie、不跟随跳转、不走 HTTP 缓存 | 跟随跳转可能把请求发到别的源；改坏这一条，跳转用例就失败 |
| 内容必须是 KDBX，否则按错误处理 | HTML 登录页也可能是 200 |
| 连接在响应前断开时不猜，读回来判断 | 服务器可能没写、写完或写了一半；三种情况客户端看到的都是同一个网络错误 |
| 只接受 HTTPS；明文 HTTP 只接受本机 | ADR-0003 禁止降级 |
| CSP 的 `connect-src` 要列出同步地址；用 `securitypolicyviolation` 事件区分原因 | CORS、CSP、断网在 fetch 里是同一个 TypeError，只有这个事件能告诉用户是部署没放行 |

## 结果

Chrome 154.0.8037、Edge 156.0.4314、Firefox 157.0（Playwright 补丁版）、WebKit 27.2（Playwright 版）、官方 Safari 27.0，**下面每一行五个浏览器结果相同（共 23 个服务器用例和 4 个客户端用例）。** 页面都在严格 CSP 下运行。服务器和页面都在本机回环地址上，走明文 HTTP。

| 用例 | 结果 |
| --- | --- |
| Apache：探针、防覆盖创建、条件替换 | 通过 |
| Apache：A 读 → B 提交 → A 用旧基线提交（M07） | A 收到冲突，远端保留 B；A 写冲突副本后主文件不变 |
| Apache：错误密码、没带密码 | 都是认证错误，没有弹浏览器登录框，请求没有挂住 |
| Apache：PROPFIND Depth 0 | 207，读到的 ETag 和 GET 一致 |
| WsgiDAV：探针 | 判定不安全，缺 `etagChanges` |
| WsgiDAV：强制走一遍（只为验证判定） | **旧基线提交真的盖掉了别人的版本**，判定没有冤枉它 |
| 没有 CORS | 连不上，明确报错 |
| 不暴露 ETag、没有 ETag、弱 ETag、ETag 只到秒、忽略条件 | 判定不安全，**目标文件没变**，冲突副本写成功 |
| HTML 登录页 | 拒绝，不当作 KDBX |
| 跨源、同源跳转 | 读写都拒绝；跳转目标收到 0 个请求，认证头没有泄漏 |
| 服务器说可以缓存 | 仍读到最新内容 |
| 写完才断开 | 读回后确认已提交 |
| 没写就断开 | 确认没提交，远端没变 |
| 写了一半才断开 | 报“变了或被截断”，不说已提交 |
| 只剩半截头部 | 报“已损坏” |
| 403、423、429、507、500 | 各报各的错误类别，不重试覆盖 |
| 不在 CSP 里的地址 | 连不上，且收到违规事件 |
| 明文 HTTP 地址（非本机） | 构造时就拒绝 |
| 跑完后 localStorage、sessionStorage、IndexedDB、CacheStorage | 全空，密码没有落盘 |

服务器的表现（上面第一张表）用 Node 裸 socket 测，和浏览器无关：浏览器里本机传得太快，中断来不及生效，我最初的浏览器内中断测试实际都是传完才断，已删除。

## 过程中查出的问题

- **WsgiDAV 的 `expose_headers` 配置没进实际响应，** 只进了预检响应（mw/cors.py，规范要求相反）。照文档配置，浏览器永远读不到 ETag，表现是“连得上但不能写”。测试里用 `add_always` 绕开。上游没报。
- **`Access-Control-Allow-Headers: *` 没有拦住 Authorization。** 规范说通配符不包含它，但三个引擎实测都放行。客户端看不到这个响应头，所以判断不了部署配得对不对；部署文档要明确写精确来源，不能靠浏览器兜底。
- **Apache 停止时向整个进程组发 SIGTERM。** 和驱动同组会把驱动一起杀掉，还不留任何报错。测试服务器要放进单独的进程组。这只影响测试工具。

## 验证

- **故意改坏（Chrome，均为实际运行）：** 跟随跳转、不校验 KDBX、不看能力报告、替换不带 If-Match、断线后不读回、不查 ETag 变化、弱 ETag 不重读、接受明文 HTTP、把弱 ETag 当强，9 种都被抓到。
- **没有独立的红灯阶段：** 代码和用例一起写的，上面的改坏检查是替代手段。

## 还没解决

| 项目 | 情况 |
| --- | --- |
| **探针测不出“上传中断会截断”** | 这是最大的缺口。浏览器里没法可靠地制造中断，所以 ETag 精确但 PUT 不原子的服务器能通过探针。现在的保护只有两层：本地副本在确认前不能丢，断线后如实报告。K084 要决定是否在替换前先写一份随机名字的备份 |
| 先传临时文件再条件 MOVE | Apache 上可行（过期 412，正确 204）。**WsgiDAV 忽略 MOVE 的 If 条件，过期也照样改名**，所以不能默认使用，要单独探测；还要求部署方放开 MOVE、Destination、If、Overwrite |
| 真实服务 | **只测了 Apache 和 WsgiDAV。** Nextcloud 没测：`nextcloud:31-apache` 镜像拉了 20 多分钟卡在最后几层，放弃了，对接代码也没留，免得留下没跑过的代码。坚果云、群晖等也没测。结论不能外推，这正是必须现场探测的原因 |
| HTTPS | 全程本机明文。证书错误、混合内容（HTTPS 页面连 HTTP 的 NAS）、本地网络访问授权都没测 |
| 真实跨设备并发 | 这里只有同一浏览器内的两个客户端对象 |
| 大文件 | Playwright 会转发请求体，太大它自己崩，探针只用了小文件 |
| 恶意 XML、响应超大 | 大小上限写了但没有用例；PROPFIND 只跑了正常路径 |
| 官方 Firefox、真机 | 同 [K071](K071.md) |
| OneDrive 全部 | 没开始，需要专用测试账号。先核对：[有报告说](https://help.nextcloud.com/t/unable-to-connect-microsoft-email-account-to-mail/245632)微软登录页开始发 COOP 头，弹窗和页面的联系会被切断；ADR-0007 首选的弹窗授权要实测，这只是别人的报告，没验证 |

K072 保持 DOING。这些结论不代表任何真实 WebDAV 服务可用。
