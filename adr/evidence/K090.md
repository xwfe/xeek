## 3. capabilities：实际默认与调用链

以下路径/行号均指固定提交，非 `/tmp/nsh` 滚动 HEAD：

1. `crates/nsh-engine/src/lib.rs:299–340`：`Policy::default()` 的 declared/granted 都为 None；`Policy::access()` 在缺 declared 时调用 `Capabilities::all()`。所以“未配置”**不是默认拒绝**。
2. `crates/nsh-core/src/access.rs:1082–1111`：`Capabilities::all()` 是 legacy 权限：HTTP 任意 host、webview、状态栏、剪贴板、picker、share、speech、通知、audio、application、homeDir、openUrl、普通窗口可用；raw sockets/process/fs/host 函数仍需显式声明。不能称“所有系统权限任意执行”。
3. 同文件 `Access:2017–2041`：`each` 对声明和可选 host grants 取交集；`granted=None` 不收窄声明。显式 `{}` 解析为缺省拒绝集合，与省略 capabilities 不同。
4. CLI `crates/nsh-cli/src/test.rs:529,842` 将 built capabilities 交给 bundle 的 `with_capabilities_json`；`nsh-engine/src/access.rs:101` 在 HTTP dispatch 前调用 `allows_http`。网络拒绝的错误契约位于同文件开头。`website/modules/nsh.md:1338–1339` 规定 openUrl 无授权返回 `ERR_ACCESS_DENIED`。
5. 宿主：Android `crates/nsh-platform-android/java/com/longbridge/nsh/NshView.java:252` 的 `setGrantedCapabilities`；iOS `crates/nsh-platform-ios/src/view.rs:123–126` → `surface.rs:841–842` 写入 bundle policy；Swift `grantCapabilities` 见 `website/docs/ios.md:226`。宿主必须先设 `{}` 再加载，并验证设置成功。我们只提供 grants 输入文件，**没有实现/跑通宿主**。

为尝试反驳“显式最小配置也不收窄”的可能性，检查了默认 all 与显式空对象两条分支、交集函数及 CLI 声明传递；未发现 Storage/grants 文件自动接线。CLI 反例已实跑，network/openUrl 均返回 ERR_ACCESS_DENIED；这不扩称为原生宿主 grants 或浏览器已验证。

最小实验 `nsh.json` 明确 `capabilities: {}`：不开放 network/openUrl/任意文件/clipboard/windows/host。页面不加载外部图标、字体、资源，不调用 Storage。Storage 没有独立 capability，不能用虚构的 `storage: false` 当安全控制。

Storage 的官方实现契约见 `website/modules/nsh.md:2827–2872`：5 MB 字符串键值，移动/桌面是 storage.json，Web 是 app id 前缀 localStorage，写盘后台进行；不是安全存储或 KDBX 事务。只允许非敏感显示偏好。Clipboard 普通 API（同文件 `1550` 起、`1872` 拒绝说明）没有 keex 所需全部敏感标记/过期/锁库/条件清理保证，K092 另验；当前不给权限。
