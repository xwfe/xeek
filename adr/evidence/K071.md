# K071 证据：浏览器文件、密文缓存、配额、单写者与恢复

日期：2026-10-30。状态 **DOING**。依赖 K001、K068 还在 REVIEW，所以这是不依赖其结论的合成预实验：只用公开合成库，不接真实数据，不开放任何写入。实验代码和复现方法见 [tests/web_storage](../../tests/web_storage/README.md)。

## 结论先说

**浏览器这条路在本机测过的范围内走得通，没有发现阻塞项。** 密文缓存、单写者、配额和磁盘写满、BFCache、下载语义都有明确的安全路径，但**授权后写回真实文件还没测**，因为权限弹窗只能人点。

| 决定 | 依据 |
| --- | --- |
| 密文缓存只用 IndexedDB，不用 OPFS | 新版本、版本指针和条件检查放在同一个事务里，全成功或全不变，不用自己写两阶段提交。Firefox 隐私模式下 OPFS 直接报 SecurityError，IndexedDB 能用 |
| 用户选中文件时立刻读完并记下哈希，之后绝不重读 | 磁盘上的文件变了之后再读，三个引擎三种结果；**Firefox 悄悄返回新内容，没有任何报错** |
| 离开页面就释放写锁，恢复后重新申请 | 持锁的页面能进 BFCache。Chromium 在别的标签抢锁时会驱逐它，其它浏览器没测到，不依赖这个行为 |
| 离开页面就撤销会话 | Chrome、Edge、真实 Safari 都实测从 BFCache 恢复了旧的 JS 堆，页面上的内存状态确实还在 |
| Web Locks 只防误操作，条件提交才是保险 | 去掉锁判断后，旧基线的提交仍被版本条件拒绝 |
| 下载只能说“已交给浏览器” | 页面无从得知用户是否取消、存到哪里；取消和完成时显示完全相同 |
| 写回文件前核对哈希，但不把它当成条件提交 | 本地文件系统没有 CAS，核对和替换之间仍有很短的窗口 |

## 过程中查出的问题

- **Firefox 磁盘写满后会强制关掉数据库连接。** 之后每次调用都抛裸的 InvalidStateError，第一版实现没包住，调用方会拿到意料之外的错误类型。已修：统一成 `unavailable`，界面应提示重新打开。写满时 Firefox 和 WebKit 给不出错误对象，所以 `unavailable` 要同时覆盖“存储不足”，界面不能只说“配额不足”。
- **全零测试数据是假的。** IndexedDB 内部会压缩，第一版用全零填充既撑不满配额，耗时也失真。真实密文不可压缩，改用伪随机数据。
- **持久上下文加 `--incognito` 不生效，** 重启后数据还在，说明测到的根本不是隐私模式。Chromium 改用非持久上下文，它和隐身窗口是同一种配置类型，但不是界面上的隐身窗口。
- **`createWritable` 没有写权限时不会失败，而是弹授权框一直等。** 界面不能把这段等待说成“正在保存”。
- **Firefox 的配额配置项不生效。** `dom.quotaManager.temporaryStorage.fixedLimit` 设了之后 `estimate()` 还是 10 GiB，所以改成把配置目录放到小磁盘镜像上，真正写满。

## 验证

- **故意改坏（Chrome，均为实际运行）：** 分别去掉条件提交、旧版本清理、写锁互斥、读取校验、写前核对、离开页面撤销会话，6 种都被对应场景抓到。
- **没有独立的红灯阶段：** 被测代码和场景是一起写的，上面的改坏检查是用来代替的。
- **偶发现象，没有查清：** 完整流程里 Chrome 的 `twoTabs` 有一次报“浏览器被关闭”，之后单项重复 8 次、完整流程 3 轮都没再出现。Firefox 曾有一次 150 秒超时，当时 `goBack` 在等 BFCache 恢复时不会触发的 `load`，这很可能是原因，修正等待方式后完整流程 3 轮没再出现，但没有证据证明就是它。

## 还没验证

| 项目 | 为什么 | 怎么解除 |
| --- | --- | --- |
| **授权后写回真实文件、撤销权限、拒绝授权、`.crswap` 残留** | 权限弹窗和系统文件框只能人点 | 打开 `/manual.html` 走一遍，约 5 分钟 |
| 官方 Firefox | 本机没装；Playwright 版打过补丁 | 安装官方版，或在有它的机器上跑 `?auto=` |
| Safari 的杀进程、下载、隐私模式、磁盘写满 | 没开远程自动化；隐私窗口只能手动 | 开 Safari 的“允许远程自动化”后接入驱动 |
| Firefox、WebKit 的 BFCache | Playwright 下没恢复，配置项也没用 | 官方 Firefox 跑 `?auto=`；Safari 已测 |
| 浏览器真实驱逐 | 只用页面脚本模拟了数据被删 | 难以触发，K082 再评估 |
| 断电 | `kill -9` 杀的是进程，操作系统页缓存还在，证明不了真正落盘 | 需要真机拔电或虚拟机 |
| iOS Safari、Android Chrome | 没有设备 | 同一探针页走 HTTPS 部署后在真机打开 |
| 多文件写回的原子性、不同文件系统 | 只测了本机 APFS | K082 |

这些结论不覆盖 KDBX 解析和 KDF：K070 才验证浏览器里的 writer。K071 保持 DOING。
