# K011 预实验证据：用 forui 搭界面

日期：2026-11-06。K011 仍是 TODO，它依赖的 K010 骨架还没开始，所以这是不依赖其结论的界面预实验：只用公开合成数据，不读写密码库。实验代码和复现方法见 [tests/forui_candidate](../../tests/forui_candidate/README.md)。用哪个组件库由项目负责人决定，本文只给证据。

## 结论先说

**forui 0.27.7 可以当 keex 的主组件库，但它有 7 处默认值达不到 keex 的要求，要在 keex 这边补。** 补上以后，这次覆盖的读屏、200% 大字、中文输入和 Web 严格 CSP 都过了。另有两个问题出在 Flutter 本身，换组件库也躲不开，见下一节。

| 要补的地方 | forui 默认 | keex 怎么补 | 依据 |
| --- | --- | --- | --- |
| 秘密输入框 | 自带密码框总把字段报给系统自动填充，提示固定是“密码”，不能传 null；允许输入法个性化学习 | 用 forui 的普通输入框拼 keex 自己的秘密框：自动填充提示传 null，关掉个性化学习 | Android 实测见下文。Flutter 只有收到 null 才关自动填充，空列表照样上报 |
| 日期框 | 只读输入框。Flutter 的只读输入框不给读屏“点击”动作，Android 上是能聚焦、不能点击的节点 | 包一层，把点击动作并进同一个读屏节点，打开的仍是 forui 的日历 | Android 无障碍树、组件测试、forui 与 material_ui 源码 |
| 点击区域 | 页头按钮 44×44，侧栏项高 44，密码框“显示”按钮 40×40，普通按钮高 44（单位 dp） | 页头按钮和侧栏项各补 2 的内边距；图标按钮和主按钮用 forui 的 lg 尺寸 | Android 要 48dp，iOS 要 44pt（[设计说明 §4](../design/README.md)） |
| 大字换行 | 列表项文字截成一行加省略号；页头标题写死单行 | keex 自己的文字控件显式写换行参数，页头放宽到两行 | [移动体验基线 §3](../design/BITWARDEN_MOBILE_REFERENCE.md) 要求“放大文字后内容换行” |
| 字体 | 主题默认用 forui 自带的 Inter | 主题里改成平台字体名，Android 是 Roboto，iOS 是 CupertinoSystemText，中文由系统回退 | 原型要求中文走系统字体 |
| Material 来源 | forui 建在从 Flutter SDK 拆出来的 material_ui、cupertino_ui 包上 | 页面也用这两个包，不用 SDK 自带的 `package:flutter/material.dart` | 混用会让应用里有两份 Material，主题和本地化各管各的。这是读源码的判断，没做混用实验 |
| 版本 | 还是 0.x，小版本都带破坏性改动 | 写死 forui 0.27.7、material_ui 1.10.0、cupertino_ui 1.1.6，升级当单独任务做 | CHANGELOG 里 0.24、0.25、0.26、0.27 标了 Breaking 的条目分别有 13、10、4、6 条 |

**还有一项去不掉的成本：** forui 在自己的 pubspec 里声明了 Inter 字体，正体加斜体共 1.7 MiB。Flutter 没法剔除依赖包声明的字体，所以 APK 里一直带着它；Web 启动时也会整份下载，哪怕页面根本不用。

**prism_ui 没进实验。** 它 2026-11-01 才发布，0.1.2 版，GitHub 10 个 star，pub.dev 1 个点赞，只有一位作者。许可证是 GPL-3.0，用了它整个 keex 就得按 GPL-3.0 发布，这正是 K009 还没定的发行许可证问题。它的源码引入了 dart:io，进不了浏览器；也只有 iOS 风格，和基线要求的 Android 用 Material 不符。

## Flutter 本身的两个问题

**1. Web 上中文默认显示成方块。** Flutter Web 用不了操作系统的字体，遇到中文会按引擎里写死的清单，去 `fonts.gstatic.com` 下载 Noto Sans SC 的分片。keex 的 CSP 不放第三方字体（[THREAT_MODEL](../THREAT_MODEL.md) T8、[ADR-0007](../0007-web-vault-client.md)），请求全被拦下，三个浏览器里所有中文都成了方块，英文和数字正常。

解法已验证：把引擎清单里的 97 个分片镜像到自己的站点，一共 2.3 MiB；再在启动脚本里把 `fontFallbackBaseUrl` 指到本站。之后中文正常显示，第三方请求是 0，列表和详情两页只按需拉了 9 片、共 277 KB。要注意两点：

- 改了这个地址以后，所有回退字体都从本站取。没镜像的文字，比如日文、韩文、emoji，会取不到、照样显示方块。要不要一起镜像，留给 Web 的正式任务定。
- 分片清单跟着 Flutter SDK 走，升级 SDK 后要重跑 `mirror_fonts.mjs`。字体许可证是 SIL OFL 1.1，允许自托管和随应用分发。

**2. Web 开着读屏时，打拼音会被提前处理。** 在 Chrome 里打开 Flutter 的读屏树后，从第二次拼音组合更新起，Flutter 交给页面的值就不带组合区间了。搜索框因此按拼音字母先过滤了一遍：打 “shili” 还没选词时，列表显示“共 0 条”。不开读屏的普通路径没问题。这一条和 forui 无关，组件测试里同样的过滤逻辑是对的。只在 Chrome 测了，因为 Firefox、WebKit 的 Playwright 没有发组合事件的接口。有没有上游 issue 还没查。

## 结果

环境：Apple M1 Pro，macOS 26.6.2，Flutter 3.47.7（Dart 3.13.5），forui 0.27.7，Playwright 1.64.1。Android 用本机已有的 Pixel 7 Pro 虚拟机，Android 11，arm64，密度 3.5，以只读模式启动，关机后连 App 带设置一起丢弃。Firefox 和 WebKit 是 Playwright 的构建，不是官方发行版；WebKit 不等于 Safari。

点进输入框后，系统输入法实际拿到的配置：

| 输入框 | inputType | imeOptions | 输入法个性化学习 |
| --- | --- | --- | --- |
| keex 秘密框，遮住时 | 0x80081 | 0x3000006 | 关 |
| forui 自带密码框 | 0x80081 | 0x2000005 | 开 |
| 标题，普通输入框 | 0x8001 | 0x2000006 | 开 |

怎么读这两个数：inputType 的 0x80 是“密码”，0x80000 是“不联想”，0x8000 是“自动纠错”。imeOptions 的 0x1000000 是“不让输入法学习”，0x2000000 是“不进全屏编辑”，末位 5 和 6 是回车键显示“下一项”和“完成”。

秘密框起初一直用“可见密码”键盘类型，遮住时系统拿到的也是“可见密码”。现在改成遮住时用普通类型，Flutter 会因为遮挡报成标准的密码类型。

**替换边界：** 主题集中在 `theme.dart` 一处；秘密框、日期框、动态口令是 keex 自己的组件；其余页面直接用 forui 组件。以后换库，只动这三块和页面。pub 从 `pub.flutter-io.cn` 镜像取包，forui 0.27.7 的 sha256 与 pub.dev 一致。

## 没覆盖的

- **iOS 全部没跑。** 本机缺 iOS 模拟器运行时，也没连 iPhone，所以 VoiceOver、Dynamic Type、iOS 输入法和操作表的真实样子都没看。只在组件测试里用 iOS 平台变体测了操作表和转场类型。
- **读屏只看了数据，没听。** 模拟器镜像里没有 TalkBack，从商店装要登录谷歌账号，这次没装。无障碍树是 TalkBack 读的数据来源，但看过树不等于听过朗读、试过双击。
- **真实中文输入法没测。** 模拟器没装中文输入法，只测了 Flutter 层的组合态；Web 是用 Chrome 调试协议模拟的组合事件。
- **性能没测。** 1 万条列表的滚动帧率要在真机上量，模拟器的数不能代表真机，这次 Pixel 9 Pro 没连。
- **浏览器范围有限。** 官方 Safari、Firefox 正式版和手机浏览器都没跑。
- **读屏模式拼音问题没查上游。** 不知道 Flutter 有没有已知 issue 或修复版本。
- **这只是实验页，不是 K011 的交付。** 中文 ARB、正式的五导航和响应式组件仍归 K011。
