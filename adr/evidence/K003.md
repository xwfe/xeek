# K003 证据：两个候选写入库的同样本读改写对照（预实验）

日期：2026-10-22。状态 **DOING**。依赖 K002 仍为 REVIEW、K069 仍为 DOING，所以这里是“不依赖其结论”的合成预实验：结论只用于选型讨论，**写入闸门保持关闭**，不接真实库。

## 结论先说

两个候选都**没有通过无损**，都不能直接当生产 writer。各自卡在不同地方：

| 维度 | keepass-rs 0.15.3（Rust） | kdbx.dart 2.5.0（Dart） |
| --- | --- | --- |
| 许可证 | MIT | **GPL-3.0**：链接进 keex 就得整个应用按 GPL-3.0 发布 |
| 能写的版本 | **只写 KDBX 4.1**；3.x、4.0 返回 `UnsupportedVersion`（`db/save.rs:17`、`format/kdbx4/dump.rs:31`）。要保存旧库只能升级格式 | 原版本写回（3.1/4.0/4.1 实测保持）；`upgrade()` 只能把 3.x 升到 4.0 |
| 能打开的算法 | AES-KDF、Argon2d、Argon2id；外层 AES、ChaCha20 | AES-KDF、Argon2d。**不支持 Argon2id**（任何版本）和 **KDBX 3.1 外层 ChaCha20** |
| 字段/历史/附件 | 全部当前与历史字段值、保护标记、附件字节保留 | 值和附件字节保留；**空标准字段的 `Protected` 标记被丢掉**（每库 31–35 处） |
| 其它语义差异 | 根分组子节点重排；两个默认 `IconID` 被删；新历史插在**开头** | 根分组子节点重排（与 keepass-rs 排成同一顺序）；**4.1 新增的 Meta 元数据被丢**：自定义图标的 `Name`/`LastModificationTime`、Meta CustomData 项的 `LastModificationTime`；新历史追加在末尾（与 KeePass 一致） |
| 第三方再编辑 | KeePassXC 2.7.12 能重开并再改全部 12 份 | KeePassXC 2.7.12 能重开并再改全部 8 份 |
| 速度/内存（同输入） | 0.14–0.23 秒，峰值约 9.7 MB | **7.9–11.2 秒**，峰值约 51 MB |

对后续任务的直接影响：

- **K009 必须先定发行许可证。** 选 kdbx.dart 等于选 GPL-3.0；选 keepass-rs 则要接受“保存 3.1/4.0 库必须升级到 4.1”，按 ADR-0001 §3 做备份 + 告知 + 用户确认，不能静默升级。
- **新库默认 Argon2id（ADR-0001 §5）与 kdbx.dart 冲突**：它连这样的库都打不开。
- 两者的已知差异都要上游修补或自行补丁后重跑全矩阵；在那之前写入闸门不开。

## 怎么做的

- kdbx.dart 一侧：新增 [helper 与生成器](../../tests/dart_candidate/README.md)，读已登记的公开合成库 → 改一个 UserName → 保存为新文件；用独立 oracle 逐项核对，再让 KeePassXC 导出核对字段、并在副本上再改一次。清单 [dart_writer_manifest.json](../../tests/fixtures/kdbx/dart_writer_manifest.json) 记录每份输出的哈希、全部差异、KeePassXC 自身变异、耗时和峰值内存。
- keepass-rs 一侧沿用上一轮的 [12 份参考输出](K002_LIBRARIES.md)，本轮补上同样的 KeePassXC 再编辑检查。
- 两边共用同一套字段/附件比较函数（`tests/reference_writer/generate.py` 的 `compare_fields`/`compare_attachments`），口径一致。

输入（全部公开合成或固定上游原件）：

| 输出 | 输入 | 版本 / 外层 / KDF |
| --- | --- | --- |
| dk31/40/41-vault | v31/40/41-vault-edit1（KeePassXC 2.7.12） | 各自版本 / AES / AES-KDF 100 万轮 |
| dk31/40/41-passkey | m31/40/41-passkey-edit1（KeePassXC 2.7.12） | 同上 |
| dk40-upstream-argon2d-chacha20 | kdbxweb 原件 Argon2ChaCha.kdbx | 4.0 / ChaCha20 / Argon2d |
| dk41-rs-vault-argon2d-chacha20 | keepass-rs 输出 rs41-vault-argon2d-chacha20 | 4.1 / ChaCha20 / Argon2d |

另有 3 个预期失败输入：kdbxweb 的 Argon2id.kdbx（4.0）、rs41-vault-argon2id-aes（4.1）、kdbxweb 的 AesChaCha.kdbx（3.1 外层 ChaCha20）。helper 都报 `database_open_failed` 且不产出文件；独立 oracle 能正常读这三份，说明是候选能力缺口，不是样本坏了。原因已对源码确认：`key_encrypter_kdf.dart` 只登记 Argon2d 与 AES-KDF 两个 KDF UUID；`_loadV3` 固定按 AES-CBC 解密。

## 实测细节

**版本与算法**：8 份输出的版本、外层密码、KDF 参数、内层流和压缩都与输入相同；KDF 盐每次都换（2.5.0 修复了“保存不换盐”的缺陷，之前版本不要用）；3.1 的 HeaderHash 正确。

**空标准字段丢保护标记**：例如空的 Password 原来是 `<Value Protected="True"/>`，保存后变成无属性。KeePassXC 再读时又按自己的默认策略标回受保护，所以导出结果和 kdbx.dart 输出不一致。现有语义比较器把“空的五个标准字段”有意视为等价（见 `semantic.py` 的 `_is_empty_standard_field`），所以 `diff` 命令不报这一项；生成器单独逐处登记，非空值或自定义字段的保护变化仍判失败。

**4.1 元数据**：kdbx.dart 按自己的模型重写 Meta，丢了 4 处 4.1 字段。KeePassXC 再编辑时会把 CustomData 的时间补回，但图标 `Name` 补不回——一旦经过 kdbx.dart 保存，这部分数据就没了。

**KeePassXC 自身变异**（单列，不算候选的问题）：再编辑会改 `_LAST_MODIFIED`、`KPXC_RANDOM_SLUG`，把被 keepass-rs 删掉的 IconID 补回，把根分组顺序改回自己的写法；对 kdbxweb 原件还会新增 Meta/CustomData，并改附件保护属性。

**资源**（Apple M1 Pro，macOS 26.6.2，每项 3 次，`/usr/bin/time -l`，含读取和保存两次 KDF）：

| 输入 / 算法 | keepass-rs | kdbx.dart |
| --- | --- | --- |
| v41-vault-edit1，AES-KDF 100 万轮 + AES | 0.14 / 0.18 / 0.23 秒；9.7–9.8 MB | 7.85 / 9.87 / 11.21 秒；51.2–52.1 MB |
| Argon2d 8 MiB × 2 次 + ChaCha20 | 0.08 / 0.09 / 0.12 秒；18.0–18.5 MB | 0.51 / 0.61 / 1.85 秒；52.9–54.4 MB |

第二行两边输入不完全相同（keepass-rs 从 AES-KDF 库改存成 Argon2d，kdbx.dart 读的是 Argon2d 库），只能看量级。生成时清单里记的单次耗时受机器负载影响（例如 Argon2d 案例 4.5 秒），以上表为准。这只是本机合成数据，不是手机、iOS 扩展或浏览器的预算。

## 验证

仓库根目录（Python 3.12，cargo 需在 PATH 中）：

~~~sh
python3 -B tests/dart_candidate/generate.py
python3 -B tests/run_python_tests.py --suite oracle --pattern test_dart_candidate.py -v
python3 -B tests/run_python_tests.py
~~~

`test_dart_candidate.py` 共 18 项：依赖与来源锁定、产物报告可复现、版本/算法/换盐、历史追加、剩余差异与保护标记逐处登记、不支持输入、错误密码/密文损坏、6 类保留检查反例（含盐复用）、KeePassXC 重开与再编辑（两个候选都跑）、实时调用的错误码与不覆盖、生成器无操作和拒绝覆盖。生成过程中第一次运行因空字段保护标记被严格比较拦下，第二次因 KeePassXC 导出又把标记补回被拦下；两次都是真实差异，改为逐处登记后才生成，没有放宽其他比较。

## 没做的与限制

- 没测：Twofish、KeePass 官方客户端/KeeAgent/手机客户端写的库、1k/10k 规模库、附件很大的库、取消/崩溃/并发保存、Web（Dart→JS/Wasm 或 Rust→Wasm）运行时。
- kdbx.dart 的 pointycastle Argon2 在浏览器里能否跑、跑多慢、会不会卡主线程，属于 K070。
- 两个候选的差异都还没尝试修补；也没有向上游报告。
- 本轮依赖：kdbx 2.5.0 及其 38 个传递依赖（含 dio、argon2_ffi_base）装在 `tests/dart_candidate/.pub-cache/`，没有改全局环境；许可证与供应链审查只核了 kdbx 本身（GPL-3.0）和 pointycastle（MIT），其余未逐个审。
- 复核：只有主会话自测，没有独立审查；按 AGENTS.md，协议兼容性和加密写入结论必须独立复核后才能进入 REVIEW/DONE。
