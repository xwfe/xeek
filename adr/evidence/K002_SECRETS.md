## 目标与输入基线

补齐提交前本地秘密扫描，防止只检查工作树、只查新增行或按整个测试目录豁免。默认读取完整 Git 暂存树与同一份 policy；另提供显式工作树检查。工具不解密 KDBX、不在线验证凭据、不输出候选值或原路径。

开始时 HEAD 为 `2bd1f52`，工作树已有 100 条未提交状态项且暂存区为空。本轮只提交新扫描工具和可单独定位的文档增量；不将此前领域模型、读取器、参考保存或样本一并暂存。既有 KDBX、密钥文件、清单和设计原件只读核对，没有重写。

对照[真实数据规则](../REAL_DATA_RULES.md)的 L0 与[威胁模型](../THREAT_MODEL.md)中主密码/密钥、解密内容、库密文、元数据和同步凭据边界：未登记容器和二进制会阻断，报告限制外泄内容，扫描不调用网络验证。它是开发检查，不是针对恶意同用户进程或被替换依赖的隔离措施，也不证明运行时授权、密码学或生产日志安全。

## 登记来源与批准含义

本轮逐一核对既有清单中的固定路径/摘要与实际文件。登记共 95 份：82 KDBX、7 密钥文件、6 原始设计二进制。KDBX 来源分为原 37 份、领域 9 份、多 Passkey/规模 17 份、上游公开原件 3 份、Rust 参考输出 12 份、不压缩负载 4 份。六份设计二进制另与已提交的原始字节核对。

文本例外覆盖 30 个路径、31 个明确版本：包括公开算法标识/向量、样本生成源码、固定清单、测试标记和原始设计示例。同一路径的两个 reader 版本各自绑定整文件摘要，以兼容已有 HEAD 与未提交工作树；这不是两个同时存在的文件。

`kind` 是审阅分类，程序只核对内容身份，不自动证明来源公开、数据合成或文件内部安全。整文件批准可以让对应路径暂时不存在；报告只计当前快照中实际存在且匹配的文件。文本例外只放行指定规则，其他规则仍扫描；源码或路径一旦改变，该版本例外失效。新批准必须审查来源、完整内容和理由，不能自动刷新摘要消除报警。

本轮来源审阅和模型复核不替代人工独立审查。规则不能判定任意个人资料是否真实，也不能以发现结果自动建立可信来源。

## 失败行为与修复

| 具体问题 | 修复与反例 |
| --- | --- |
| 库的候选摘要可能只代表私钥头或令牌捕获组 | 例外改为完整文件 SHA-256；替换私钥正文、追加同一标记、修改令牌正文、复制到其他路径均不能继承例外 |
| 受控输出作用域跨越 generator yield | 先在静默作用域内收集结果，恢复调用方输出后再 yield；验证外部输出状态恢复 |
| 初始化失败残留第三方 settings | 已进入的 context 在失败时退出；验证清理路径 |
| 安装元数据正确但已预加载全局模块 | 检查实际导入模块及已加载子模块来源；拒绝项目依赖目录之外的版本 |
| 工作树修正掩盖已暂存秘密，或工作树 policy 放行暂存内容 | 默认读取 index blob 和 index policy；两种内容/policy 方向都测 |
| 备用 index 相对路径及链接换向 | 从启动 cwd 拼接相对路径，保留链接与 .. 语义；扫描中将链接从干净 index 换向另一份 index，结束检查拒绝 |
| XML 前言正则组合式回溯 | 改用单向游标和 bytes.find；独立子进程带 5 秒上限，测试 4096 次处理指令、注释和混合前言，有/无目标根均核对 |
| 环境示例无引号赋值漏检 | 两个确切 basename 映射到配置语法；.env.example/.env.sample 分别验证有/无引号值；原路径不传给第三方 |

最后三处问题先运行失败回归，会话 `98b1e4fe-2d58-43d9-bad7-a2bc5a27cc6c`：3 个测试方法得到 3 个失败与 1 个超时错误，确认问题存在。修复后的五项定向回归通过，会话 `d5669131-c446-4dd5-98dd-030a1f34f64e`，包含相对 index 和同长度/恢复 mtime 的工作树变化检查。没有将失败记录改写为成功。

其余覆盖包括：未知/重复 policy 字段、冲突 stage、Gitlink/符号链接、已强制暂存的忽略文件、删除文件、缺失 blob、UTF-16/无效 UTF-8/控制字节、库备份后缀与魔数、XML 前言、单文件/文本/行/总量预算，以及报告 50 条上限仍保留全部计数。超过 2 MiB 的普通文本确实逐行扫描，不沿用搜索工具的大文件跳过阈值。
