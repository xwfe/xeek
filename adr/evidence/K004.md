# K004 证据：Flutter、Kotlin、Swift 调用同一份 Rust 核心

日期：2026-11-06（实测在 2026-10-31）。状态 **DOING**：**Android 真机通过；iOS 按项目负责人要求暂停，优先级最低。** 依赖 K001 还在 REVIEW，这是合成预实验，只用公开合成库，不开放写入。复现方法见 [tests/mobile](../../tests/mobile/README.md)。

## 结论先说

**一份 Rust 核心（`core.rs`），四个薄壳：WASM、C ABI、JNI、Dart FFI。** 在 Android 真机上，Flutter 主进程和一个不加载 Flutter 的 Kotlin 进程都能读改写合成库，结果通过独立核对；结束核心所在的进程不影响主程序。

| 路径 | 环境 | 结果 |
| --- | --- | --- |
| Kotlin → JNI → Rust，独立的 `:probe` 进程 | Pixel 9 Pro，Android 17（API 37） | 通过；主程序没开，进程里没有加载 Flutter |
| Flutter → Dart FFI → Rust，主进程 | 同上 | 通过，界面帧最长间隔 58 毫秒 |
| Swift → C ABI → Rust | Mac | 21 个用例和直接调 Rust 逐项相同 |
| Swift → C ABI → Rust，iOS arm64 | 只编译链接 | 能出可执行文件；**没运行** |
| Flutter iOS 工程 | | **暂停**：Xcode 没装 iOS 26 平台组件，约 8 GB；iPhone 也没连上 |

## Android 真机实测

每一步都是新进程，峰值内存（VmHWM）才干净。包含 Android 运行时自身约 110–140 MiB 的底数。

| 项目 | 打开 | 保存 | 进程峰值 |
| --- | --- | --- | --- |
| vault、passkey、golden（AES-KDF 100 万轮） | 18–26 毫秒 | 16–18 毫秒 | 136–138 MiB |
| 1000 条目 | 85 毫秒 | 172 毫秒 | 195 MiB |
| 10000 条目 | 526 毫秒 | 612 毫秒 | 270 MiB |
| Argon2id 16 MiB，2 次 | 47 毫秒 | 30 毫秒 | 153 MiB |
| Argon2id 64 MiB，2 次 | 113 毫秒 | 107 毫秒 | 201 MiB |
| Argon2id 64 MiB，3 次，并行 2 / 4 | 224–310 毫秒 | 189–229 毫秒 | 201–202 MiB |
| Argon2id 256 MiB，2 次 | 469 毫秒 | 483 毫秒 | 393 MiB |
| Argon2id 1 GiB，2 次 | 2.1 秒 | 2.3 秒 | 1159 MiB |

AES-KDF 在手机上很快（100 万轮约 16 毫秒，有硬件 AES），和浏览器 WASM 的 690 毫秒是两个量级。Argon2 的内存是实打实占用的，扩展进程的预算要按“KDF 内存 + 约 140 MiB 底数 + 库本身”算。

| 失败路径 | 结果 |
| --- | --- |
| 错误密码 | 普通错误 `Incorrect key`，Kotlin 和 Flutter 都一样 |
| 核心里故意 panic | 被接住，返回 `PANIC: core panicked`，进程不退出 |
| 文件要的 KDF 内存超预算 | 打开前就拒绝（`KDF_BUDGET`），不分配内存，进程峰值 109 MiB |
| KDF 跑到一半结束 `:probe` 进程 | 主程序 PID 不变，探针进程消失，系统崩溃日志里没有这个包 |
| 写出的库 | 独立 oracle 全文比较只有这次编辑；和原生补丁库语义相同；KeePassXC 能打开；两次保存随机值不同 |

## 这轮新加的

- **解锁前的 KDF 内存预算检查**（K070 的开放项）：只读文件头，超预算不分配就拒绝。WASM、Android、Mac 都实测生效。浏览器的 Worker 默认按 2047 MiB 设上限，不再等到崩溃。
- **原生壳接住 panic**：panic 穿过 C ABI 和 JNI 是未定义行为。原生目标改用 `panic=unwind` 编译并在边界接住；WASM 仍然 `abort`，因为那边整个丢弃 Worker 更干净。
- **内存真的不够时接不住**：Rust 分配失败会直接中止进程。所以要靠预算检查，以及把核心放在可以丢弃的进程里。没有在手机上故意制造这种情况，怕挤掉你手机上的其它应用。
