# 实施路线与交接计划

日期：2026-10-12。当前只完成设计/方案工作，生产实现尚未开始。任务状态以 [TASKS.md](TASKS.md) 和 [STATUS.md](STATUS.md) 为准。

## 1. 交付层级

**设计基准**：中文交互原型与架构，不装真实秘密。

**只读实验版**：能在测试设备打开合成 KDBX、验证原生扩展和代理；禁止写真实用户库。

**个人试用版**：macOS + Android + iOS 共同形成创建/打开/修改/锁库/备份/同步/填充的闭环，KDBX 写入兼容性和故障注入已通过；SSH/Passkey 哪些已实现必须明示。缺少真机/签名资源应写明平台阻塞，不能把iOS默认为以后再做。仍建议使用可恢复副本。

**正式五端版**：Android、iOS、macOS、Windows、Linux 基础密码管理功能验收；桌面 SSH 代理和目标移动平台 Passkey/自动填充达到声明的支持矩阵；第三方安全复核、备份恢复、签名发行齐备。不把“同一 UI 能启动”称为完整跨平台发布。

P2/P4 的 UI 可以依赖模拟接口并行开发，但**正式读写和原生发布必须等门槛**。P4 不是末尾才第一次研究：Android/Apple 扩展和 Windows 管道已在 P0 提前探路。

UI与基础功能的验收增量采用 [Bitwarden移动体验参考](design/BITWARDEN_MOBILE_REFERENCE.md) 的U01–U08，落在既有K/M任务下：范围搜索、模板编辑、逐字段操作、自定义字段、URI匹配、再次验证及克隆/回收站。这里只借鉴交互，不引入新账号后端，不改变安全实验优先顺序。

## 3. 优先行动

第一批：K001 威胁模型、K002 黄金样本、K003 候选无损测试、K007/K008 原生 provider 实验。它们决定项目能否安全落地，优先级高于继续绘制更多漂亮页面。

同期执行专项 [M01–M07](MOBILE_SYNC_TASKS.md)：iOS扩展写入预算、OneDrive原生OAuth/最小权限、两种云的最终提交并发反例前置验证。阶段P3才集成生产provider，不等到那时才发现数据安全能力缺失。

第二批：K004 桥接、K005/K006 SSH IPC、K009 许可证/选型裁决；门槛结果记入 `adr/evidence/Kxxx.md`。不要只提交“成功解锁一个空库”的演示。

第三批：K010/K011 与 K012–K017，做“新建合成库 → 新增条目 → 原子保存 → 用 KeePassXC/KeePass 打开 → 修改 → keex 再打开 → 锁库”纵向闭环。未经确认不安装 SDK、不使用用户真实库做实验。

## 4. 依赖与并行边界

核心关键链：`K002 → K003 → K009 → K012/K014/K015/K016/K017 → K020 → K021/K023 → K037/K038 → K040 → K062`。

原生关键链：`K004 + K007/K008 → K048/K049 → K051 → K052/K053 → K055 → K062`。

SSH 关键链：`K005/K006 + K042/K043 → K044 → K045/K046 → K047 → K055`。

Flutter 组可实现设计系统、导航和模拟状态；核心组负责 KDBX/协议与测试；原生组负责系统服务/扩展；QA/安全审查独立核对。小团队可一人兼任多个角色，但加密写入/权限判断不可完全依赖同一作者自评。多个 agent 同时工作时明确文件所有权，不并行改同一核心 schema 或生成绑定。

## 5. 估算方法

任务使用相对规模：S（局部改动或单一实验）、M（一个模块或两种状态）、L（跨进程/多平台/兼容协议）。L 任务实施前拆成可在一个迭代内验收的子任务，禁止直接用“实现全平台 Passkey”作为一次领取范围。

暂不承诺固定发布日期。P0 的实际无损修复成本、iOS 真机/签名资源、Windows 代理兼容方案，是工期的主要未知量。完成 P0 后再按团队人数、测试设备与可复用程度给出人日和迭代日期；缺设备/权限时记录 BLOCKED 和下一步，不用模拟器结果冒充真机。

## 6. 变更与失败处理

KDBX 候选失败：只读保留 → 输出缺失字段/案例 → 上游修复或换库 ADR → 重跑全部矩阵。不能做“暂时不保存历史/附件”的隐藏降级。

Passkey 互通失败：保存原字段，关闭新建/覆盖，只显示“当前版本暂不支持使用”；不得显示可登录。系统能力失败：不开放假开关，保留 UI 指引和平台原因。

同步服务不满足条件写入：保留本地及远端冲突副本，要求显式解决；不退化为无条件 PUT。扩展内存不足：调整授权/缓存和共享核心方案，不能偷偷降低用户库 KDF。

## 7. 每项任务的完成定义

每次交接填写 `adr/evidence/Kxxx.md`：目标、输入基线/版本、修改文件、执行环境与命令、结果、失败案例、未测试范围、回滚方法、后续任务。使用合成数据，禁止上传真实库/导出的秘密/凭据二维码。

`TODO → DOING → REVIEW → DONE`；阻塞用 `BLOCKED` 并写原因。DONE 必须包含可复现测试和独立门槛复核。实现任务全部从 TODO 开始；设计原型的浏览器测试不能充当其证据。
