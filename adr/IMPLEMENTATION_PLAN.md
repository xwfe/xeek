## 1. 交付层级

**设计基准**：中文交互原型与架构，不装真实秘密。

**只读实验版**：能在测试设备打开合成 KDBX、验证原生扩展；禁止写真实用户库。

**个人试用版**：Android + iOS 共同形成创建/打开/修改/锁库/备份/同步/填充的闭环，KDBX 写入兼容性和故障注入已通过；Passkey 哪些已实现必须明示，KeeAgent 数据只承诺无损保留。缺少真机/签名资源应写明平台阻塞，不能把iOS默认为以后再做。仍建议使用可恢复副本。

**正式移动版**：Android、iOS 基础密码管理功能验收；Passkey/自动填充达到声明的支持矩阵；第三方安全复核、备份恢复、签名发行齐备。

**跨端个人数据保险柜版**：在移动版基础上完成资料、关联、维护闭环与 Web 客户端；GV0–GV2、GW0–GW2 和 K089 通过。Android/iOS 与 Web 按具体能力分别验收，允许分批发布，但不能把正式移动版宣称为用户要求的 Web+移动完整交付。原生凭据提供者和关闭页面后的提醒不要求在 Web 伪装对等。

**桌面版**：不在本计划内。未来用 Rust 单独开发，启动前另写 ADR；现有桌面资料索引见 ADR-0005。

## 5. 估算方法

任务使用相对规模：S（局部改动或单一实验）、M（一个模块或两种状态）、L（跨进程/多平台/兼容协议）。L 任务实施前拆成可在一个迭代内验收的子任务，禁止直接用“实现全平台 Passkey”作为一次领取范围。

暂不承诺固定发布日期。P0 的实际无损修复成本、iOS 真机/签名资源、iOS 扩展内存预算，是工期的主要未知量。完成 P0 后再按团队人数、测试设备与可复用程度给出人日和迭代日期；缺设备/权限时记录 BLOCKED 和下一步，不用模拟器结果冒充真机。

## 6. 变更与失败处理

KDBX 候选失败：只读保留 → 输出缺失字段/案例 → 上游修复或换库 ADR → 重跑全部矩阵。不能做“暂时不保存历史/附件”的隐藏降级。

Passkey 互通失败：保存原字段，关闭新建/覆盖，只显示“当前版本暂不支持使用”；不得显示可登录。系统能力失败：不开放假开关，保留 UI 指引和平台原因。

同步服务不满足条件写入：保留本地及远端冲突副本，要求显式解决；不退化为无条件 PUT。扩展内存不足：调整授权/缓存和共享核心方案，不能偷偷降低用户库 KDF。

`TODO → DOING → REVIEW → DONE`；阻塞用 `BLOCKED` 并写原因。DONE 必须包含可复现测试和独立门槛复核。实现任务全部从 TODO 开始；设计原型的浏览器测试不能充当其证据。
