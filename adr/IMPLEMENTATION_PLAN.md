# 实施路线与交接计划

更新：2026-11-21。keex 按 [ADR-0006](0006-personal-data-vault.md) 做个人数据保险柜，按 [ADR-0008](0008-nsh-unified-clients.md) 以 **NSH + TSX 主界面、共享 Rust 核心**覆盖 Android、iOS、macOS、Windows，保留 [ADR-0007](0007-web-vault-client.md) 的独立 Web 客户端。当前仍是 P0 合成实验，尚无生产客户端或安全核心；本轮完成计划切换，不代表框架迁移完成。

任务状态唯一入口是 [TASKS.md](TASKS.md)，进展与历史证据见 [STATUS.md](STATUS.md)。个人资料任务 K068–K089 的领域细节和 VT01–VT18 见 [专项计划](PERSONAL_VAULT_PLAN.md)；NSH 迁移和桌面交付新增 K090–K096，不重编号、不重置旧任务。

## 3. 下一批怎么执行

### 3.1 先做 K090，再进入平台实验

K090 先登记候选 NSH v0.6.1 的完整提交、运行时/CLI/编译依赖、许可证和最小 capabilities；核对各端已有工具链、设备、签名资源。输出可复跑清单和资源缺口，不安装缺失 SDK，不因方案批准自行启用账号或真机权限。证据写 `adr/evidence/K090.md`。

随后以 `tests/nsh_candidate/` 做最小原型：五导航、合成列表、详情/编辑/锁库。复用 `tests/wasm_core/` 中同一 Rust 逻辑及既有 C ABI/JNI/WASM 边界；Swift/Kotlin 探针在 `tests/mobile/`。不得复制 writer 或重建领域主库。具体共享边界见 ADR-0008。

- K091：按 Android/macOS/Windows/iOS 的实际资源逐端做 UI + Rust 合成纵向闭环，1k/10k、中文 IME、键盘/读屏记录齐备；各平台独立留证。
- K092：补敏感输入、异步取消/过期回调、后台/锁屏/多窗口、文件/安全存储/剪贴板及签名运行实验；发布形态不能用开发热更新代替。
- K093：复用 K070/K071 的浏览器样本与驱动，验证 NSH HTML/WASM + Rust Worker；Chrome/Firefox/Safari 逐项跑，不直接承认旧 Flutter Web 结果。
- K007/K008：移动提供者继续原生独立实验，不能等生产 UI 才开始。它们是 GN 的必要前提，不加载 NSH/QuickJS。

**iOS 现状仍是按既有要求暂停、优先级最低，缺平台组件和可连真机。** 新路线不伪造恢复执行或资源到位；可先推进已具备条件的平台。K008/K092 缺失时 K094/GN 不能通过，任务真正领取后写明 BLOCKED 与解除条件。

## 4. 依赖与并行边界

下列是关键关系概览；完整依赖只在 TASKS 表维护：

- UI 迁移：`K090 → K091/K093；K091 → K092；K091/K092/K093 + K007/K008 → K094/GN`。
- 生产入口：`K004 + K009 + K094 → K010 → K011/K013 → K020`。K094 不依赖 K010，避免“先生产、后验证”的循环。
- 领域：`K017/K020/K068/K069 → K073 → K074–K080 → K083/K086`。
- Web：`K070–K072 + K093 + K010/K012 → K081/K082 → K084/K085 → K087/K088`。
- 桌面：`K020/K031/K039/K080/K083/K094 → K095 → K087/K096`；`K062 + K087 + K088 + K096 → K089`。
- 原生凭据和 KeeAgent 数据继续 K042–K055；SSH 代理链 K005/K006/K044–K047 留作后续，不阻塞资料客户端。

UI 负责 TSX/交互；核心负责 KDBX/领域/协议；原生负责宿主和系统扩展；Web 负责浏览器 IO/部署/授权；质量负责独立证据。小团队可兼任，安全/权限/迁移不能只靠同一作者自评。多个 agent 明确文件所有权，不同时修改 schema 或生成绑定。

## 5. 估算与失败路线

S/M/L 是相对规模，不是人日。L 任务按平台/风险切成可复跑小批，证据仍归同一 K 任务；不用另起竞争状态表。NSH 四端资源、输入/可访问性适配、iOS 扩展预算、writer 兼容和签名发行都是未知成本，P0/GN 后才排可靠日期。

NSH 硬性场景失败：保留失败样本 → 定位宿主/框架修补成本 → 更新 GN；超出可维护范围时另作选型决定。停止生产迁移，不自动恢复长期双 UI，也不放宽权限、CSP 或锁库语义换“跑通”。

KDBX 失败维持只读；Passkey 互通失败只保留资料并关闭新建/签名；同步缺条件提交时保留双方和冲突副本；扩展内存不足不降低用户 KDF。所有降级必须可见、可解释，不伪装通过。

## 6. 每项任务的完成定义

每次交接使用 TASKS 的证据模板，写入 `adr/evidence/Kxxx.md`：输入版本、修改范围、命令/环境、正常和失败结果、未运行项、资源缺口、回滚方法与独立审查结论。真实数据级别始终查 [REAL_DATA_RULES.md](REAL_DATA_RULES.md)。

`TODO → DOING → REVIEW → DONE`；阻塞写 BLOCKED 与解除条件。DONE 必须包含相应可复现测试和门槛复核。文档已更新、框架可编译、原型截图和某个候选可解锁空库都不能充当功能完成。
