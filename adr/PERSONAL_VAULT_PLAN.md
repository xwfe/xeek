GV0 = 新领域编码有独立复核和无损样本；GV1 = 资料/维护闭环，移动先行、桌面由 K095 逐端重验；GV2 = 新领域跨端并发与恢复。它们是增量门槛，不替代 G0–G5。GW0–GW2 定义见 ADR-0007，GN 定义见 ADR-0008。

阶段可以按依赖交叉进行，不强行串行：Web 文件/CORS/授权实验应在写完移动 UI 前完成；移动端不因某浏览器暂时不支持文件原地保存而降低安全或停做原生凭据。但**整体四原生端 + Web 需求尚未满足**的部分必须留在路线中，不能静默降回“以后再做”。

不设无依据的人日/发布日期。依赖缺 SDK、签名、测试设备、专用账号或授权时写 BLOCKED 和解除条件；不得为赶进度安装工具链、动真实库或自动登录用户账户。

## 3. 拟定代码边界

以下是模块边界，不是新增顶层目录清单；沿用 ADR-0008 的最小复用/目录方案，生产路径在 K010 定版：

```text
共享领域核心
  records/       类型化记录、字段保护、版本化映射
  relations/     同库关联、反向索引、缺失引用与替换计划
  lifecycle/     日期语义、维护规则、完成事件
  sync/          领域原子组接入既有三方合并
NSH/TSX 主应用
  features/records, telecom, finance, maintenance
  templates/     内置声明式模板与中文字段文案
平台适配
  mobile/        Swift/Kotlin 宿主与独立凭据扩展，直调 Rust
  desktop/       macOS/Windows 文件、安全存储、窗口、系统锁定、通知
  web/           核心 Worker、浏览器文件/密文缓存、授权/双云、生命周期
测试
  fixtures/kdbx  延续现有合成来源与独立语义比较
  vault_domain   日期/关系/迁移的纯逻辑样本
  web_contract   保存、撤权、多标签、配额、CORS、供应链/内容安全
```

优先在既有包内按模块实现，不为目录名分别建服务/crate。模板与底层凭据能力隔离；任何业务关联不得直接触发 `getOtp`、签名或填充。

## 5. 增量验收矩阵

| 场景 | 可重复输入与操作 | 通过标准 | 对应任务 |
| --- | --- | --- | --- |
| VT01 类型与投影 | 一个条目同时出现在分类和全局搜索；移动分组再打开 | UUID/条目数量不变，类型不因移组改变 | K069/K073/K080 |
| VT02 金融资料 | 一账户两卡两订阅，编辑其中一个卡号/金额 | 其他秘密与付款关系不变；金额币种整体保存；默认遮罩 | K074 |
| VT03 无号码 eSIM | 创建数据专用配置+套餐、不填手机号 | 可保存；不伪造手机号或短信能力；核实状态为未知 | K075 |
| VT04 配置替换 | 同号码线路从旧配置换新配置 | 线路身份和找回关系不变，旧配置保留历史 | K075/K079 |
| VT05 换卡一半完成 | 3 个订阅只确认 1 个改付款卡 | 仅 1 个活动关系改变，其余仍待处理 | K079 |
| VT06 停号风险 | 有登录/恢复关系时归档或删除号码 | 显示影响，不自动删除/迁移凭据；恢复可找回关系 | K073/K079 |
| VT07 日期边界 | 1月31日起月付，跨2月；闰年；夏令时/旅行 | 锚点不永久漂移，业务时区/日期精度不被设备设置覆盖 | K077 |
| VT08 保号依据 | 最近有效操作未知、点通知、撤销一次完成 | 未知不猜截止；点通知不算续费；撤销后正确重算 | K077/K078 |
| VT09 通知隐私 | 锁库触发通知，权限拒绝，删规则/移库 | 文本与 payload 无资料内容；点击需解锁；旧调度清理 | K078 |
| VT10 关系同步 | 两端同时改同边目标；一端删边一端修改 | 保留冲突，不按时钟决定，不同时出现两个“当前付款卡” | K083/K087 |
| VT11 导入兼容 | 旧库/未知类型/parentEntryUuid/重复 CSV | 不自动迁移或覆盖；预览、备份、事务、失败恢复可重放 | K069/K086 |
| VT12 浏览器保存 | 取消下载、拒绝权限、配额满、关闭标签 | 不报告原文件已保存；旧有效文件/缓存保留；限制清楚 | K071/K082 |
| VT13 多标签撤权 | A 编辑，B 保存/锁库，A 再提交；恢复旧页面 | 版本冲突或撤权拒绝；旧会话不复活 | K081/K082 |
| VT14 云并发 | A建上传会话→B提交→A完成；WebDAV忽略条件 | 最终拒绝旧基线或保留冲突副本；无静默覆盖 | K072/K084 |
| VT15 OAuth | 弹窗拦截、取消、刷新、scope不足、切账号 | access/refresh token、WebDAV密码及上传URL均不持久化；不增加权限，未保存修改不随自动跳转丢失 | K072/K084 |
| VT16 恶意内容 | HTML/SVG附件、脚本字段、外链、被污染静态资源 | 主应用不执行内容；资源策略可复现；明确无法抵御全站控制的边界 | K088 |
| VT17 库增长 | 1k/10k条目含关系/事件和小/大附件；iOS扩展冷启动 | 记录机型/版本/峰值；超额不删数据、不降KDF；预算有证据 | K069/K070/K076/K087 |
| VT18 完整恢复 | 主设备丢失，仅保留库、必要密钥和独立备份 | 新设备恢复资料/关系/规则/凭据；重新授权同步与通知，不依赖明文旁库 | K087/K089 |

VT01–VT11、VT17/VT18 的共享业务在 macOS/Windows 随 K095/K087 重验；VT09 的桌面通知另测权限/退出/休眠。桌面双云复跑 VT14/VT15 的适用授权和最终提交场景，不能拿浏览器 CORS 结果替代原生 OAuth。NSH 平台迁移的专属场景见 ACCEPTANCE 的 AC-NSH，不重编 VT 编号。

VT16 的“被污染静态资源”要求验证防护、更新策略及明确残余风险，不以注入自己可控的脚本后仍能窃取秘密为由伪称完全隔离。Web 应用在攻击者已控制全部执行代码时无法保护正在解锁的秘密。

## 6. 范围控制与失败路线

格式/库失败：保持只读，固定最小反例，上游修补或更换候选后重跑全矩阵。不得为了新模板而丢弃旧 KeeAgent/Passkey/历史字段。

Web 文件 API 不足：允许明确导出新副本或已验证密文缓存；不把降级掩盖成原地保存。CORS/CAS 不足：限制该部署/服务的自动同步或走冲突副本，不建中转明文后台。

关系/规则过复杂：减少首版操作种类，保留原始资料和手工下一日期，不引入通用图数据库/流程引擎。自动 OCR、官方余额接口、原生 eSIM 安装、完整交易记录、AI、共享和插件市场均不混进上述任务。

容量不满足：先给出可量测上限与安全拒绝；不自动把附件分散到公开云 URL 或让两个数据源共同成为权威。未来独立附件仓库需要另一个 ADR，不在本轮暗中搭建。
