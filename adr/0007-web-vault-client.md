# ADR-0007：Web 是独立验收的保险柜客户端，不是明文后台

日期：2026-10-16，客户端更新：2026-11-21。状态：**Web 纳入当前规划；运行时、存储和部署待 K070–K072、NSH 集成待 K093/GN 裁决**。本决策部分取代 [ADR-0005](0005-mobile-first-scope.md) 对 Web 仅作后续研究的安排，桌面范围后由 [ADR-0008](0008-nsh-unified-clients.md) 调整，小程序仍为后续。

## 1. 目标与交付范围

Web 目标是可管理同一 KDBX 的正式客户端：打开/解锁、资料新增编辑、关系、待办、附件、加密保存/导出、WebDAV/OneDrive 同步及恢复。不是只展示脱敏清单的管理后台，也不是移动端页面截屏。当前这些能力全部未实现。

2026-11-21 按 ADR-0008 改为 NSH + TSX 共享 UI 目标，K093 验证 HTML/WASM 与 Rust Worker；原 Flutter Web/Dart 桥实验保留作对照，停止扩建。共享 schema、核心语义和测试，浏览器 IO/授权/生命周期独立适配。NSH 的 Web 目标并不让原生 FFI、文件授权、通知、系统凭据扩展自动可用。NSH 上游依据见 ADR-0008；原 Flutter 平台说明 [PV04] 仅作为历史对照。

不在本 ADR 授权：浏览器扩展、跨网站自动填充、任意 RP 的 Passkey 提供者、SSH Agent、原生 eSIM 管理、云端明文搜索、服务器代解密、强制 keex 账户。普通网页使用 WebAuthn 登录自己网站，不等于它可以作为其他网站的通行密钥管理器。[PV14]

## 2. 运行时先验证，不凭编译标签选型

K070 保留同样本的 Rust→WASM、Dart→Web 候选对照及失败记录；现行路线收口共享 Rust/WASM 的 KDBX、CSPRNG、KDF/cipher、压缩、未知字段、取消、峰值内存、主线程阻塞和构建依赖，K093 再验 NSH UI 集成。原生 FFI 不能原样运行于浏览器。Dart 候选的许可、Argon2id 与性能限制见 [K003](evidence/K003.md)，仅作历史对照，不继续扩大 Dart/Flutter Web 生产路径；Rust 失败需另作选型裁决，不自动切回另一套 writer。

[K070 实测](evidence/K070.md)：补丁版 keepass 的 Rust→WASM 在五个浏览器可用，kdbx.dart 和 kpasslib 进不了浏览器；只需多放开 `'wasm-unsafe-eval'`；Argon2 内存上限不到 2 GiB；锁库必须结束 Worker，WASM 内存不能缩小也不保证清零。

优先一个共享 writer/语义核心、多端适配；不维护两套有不同兼容规则的生产 writer。如果确需两个运行时，必须共享格式契约、独立语义比较和全量差分样本，经独立 ADR 批准才开放。不得为浏览器降低用户库 KDF 或换成私有 AES-GCM 容器。

Worker 可用于取消与减少主线程阻塞，但 Worker/WASM 不是对同源恶意 JavaScript 的秘密隔离边界。UI 遮罩也不是字段级加密隔离。Web 解锁完整库意味着该浏览器执行环境可能接触完整库；敏感用途应明确告知，不宣传“网页只看卡片，所以私钥绝对安全”。[PV09]

## 3. 可信交付与威胁模型

Web 额外信任浏览器、加载的前端构建和静态托管更新通道。攻击面包括域名/静态站被替换、XSS、依赖/CDN、浏览器扩展、旧 Service Worker、恶意附件、多标签竞态、缓存被清理。

**首版政策**：只发布可固定版本、自托管的静态包和明确来源的部署说明；页面资源、字体、渲染依赖不默认走第三方 CDN。依赖锁定、构建清单、校验和、发布来源和版本信息可核对。固定版本/SRI/CSP 只能提高门槛，不能保证抵挡控制入口 HTML/响应头的托管攻击者。

部署必须 HTTPS（本机开发限 localhost/合成数据）。执行严格 CSP、禁止被任意 iframe 嵌入、限制外联和外部打开、纯文本安全渲染；确需 WASM 相关指令逐项说明，不能以框架兼容为由直接放开全部 `unsafe-eval`/内联脚本。附件不在主应用同源上下文执行 HTML/SVG/脚本；无法安全预览时只提供经确认的导出。

同步来源要同时满足应用校验和部署 CSP。不能把用户输入的任意 URL 自动变成可信站点，也不能为了“支持所有 WebDAV”把安全策略无条件放开。自托管配置可列允许的同步/授权域；新增域需修改部署配置并在安全保存后重新加载。托管版不允许的来源明确显示受限，不使用公共 CORS 代理兜底。

若以后加入 PWA/Service Worker，只缓存经验证的静态资源和显式启用的密文缓存；不截取主密码、库明文、同步令牌。更新不可在解锁编辑中途自动接管：先完成安全保存/提示未保存 → 锁库 → 激活新构建。首个 Web 发布不依赖 PWA 离线安装或后台推送。

## 4. 会话、缓存与文件语义

默认会话模式：手动选择 KDBX 或主动连接同步源，解锁材料和明文只留当前会话；刷新/离开后重新解锁。浏览器恢复页面不恢复授权；后台、闲置、BFCache 返回、Worker 重启均重新检查 epoch。未保存修改可能因关闭页面丢失，应明确提示；`beforeunload` 不是可靠保存机制。

可选“在此浏览器保存密文”需单独授权，仅允许经过验证的 KDBX、加密祖先/备份以及最小版本指针进入 IndexedDB/OPFS。主密码、快速解锁等效材料、解密字段、搜索词、附件预览、激活码与同步认证秘密不进入浏览器持久存储。access/refresh token、WebDAV 密码与上传会话 URL 无论有效期长短均只放受控会话内存；仅下节经 K072 列明的 OAuth 事务材料可作有限例外。浏览器缓存可能被驱逐，配额和持久化授权也不等于备份。[PV10]

保存状态必须区分：

| 状态 | 能承诺什么 | 不能说什么 |
| --- | --- | --- |
| 仅内存修改 | 当前会话内有修改 | 已保存 |
| 密文缓存提交成功 | 当前浏览器缓存有可再读验证的版本 | 永久备份、安全写回源文件 |
| 已准备/发起下载 | 新 KDBX 已加密，可交给浏览器下载 | 已替换原文件、用户已成功保留文件 |
| 文件写入并回读验证 | 该文件接口本次写入结果可验证 | 所有浏览器具有相同原子性 |
| 远端条件提交确认 | 指定 generation 被远端确认 | 此后所有本机修改也已同步 |

File System Access 等能力按浏览器和权限检测；不支持时使用显式导出新副本，不仿造原地保存。直接修改源文件只在实际事务/备份/崩溃行为通过时开放；否则保存新版本，不覆盖源文件。[PV12]

[K071 实测](evidence/K071.md)补充四条：密文缓存只用 IndexedDB（新版本、指针、条件检查同一事务）；用户选中文件时立刻读完并记下哈希，之后不重读，因为 Firefox 重读会悄悄返回磁盘上的新内容；离开页面就释放写锁并撤销会话；写回文件前核对哈希，但本地文件系统没有条件提交，不等于 CAS。

同源多标签写入优先 Web Locks + 持久版本条件；BroadcastChannel 只传撤权/失效提示，不传解密密钥或秘密。拿到本机锁不意味着远端未变化，仍要 CAS。锁 API 不可用、标签崩溃或无法证明单写者时，不退化成最后写入获胜。[PV11]

没有原生 Keychain/Keystore 等价保证时，首版 Web 不做“永久记住主密码”或短 PIN 解锁。后续 WebAuthn PRF/硬件解封如需评估应另立任务，本轮不以按钮占位声称可用。

## 5. 双云与授权

共用 [ADR-0003](0003-cloud-sync.md) 的密文对象、版本条件、祖先、三方合并和每库单一双向源规则；浏览器传输/授权实现独立。移动 provider 能成功不代表 Web 通过。

**WebDAV**：必须验证 OPTIONS 预检、允许的请求方法/头、可读 ETag、创建防覆盖、If-Match 的最终语义及跨源跳转。带凭据请求的 CORS 配置不能把任意 origin 反射或与通配符混用；按实际认证方式配置精确允许源，不照抄社区示例。缺 CORS 是“不支持此浏览器连接”，不是让用户关闭浏览器安全。[PV08,PV15]

**OneDrive**：公共 SPA OAuth 授权码 + PKCE，正确配置浏览器 redirect URI；不放 client secret，不把原生 broker 路径直接移来。MSAL 默认缓存策略不能直接接受：首选经实测的内存令牌缓存与用户触发的弹窗授权。微软文档明确 `memoryStorage` 不支持完整页面 redirect 的同等流程；弹窗被拦截时应解释并重试授权，不偷偷切到持久令牌或让未保存库内容随导航消失。[PV13]

协议必要的短期 state/PKCE 事务信息可按经审查的 SDK 流程暂存，不混入库主密钥；具体记录及清理点列入 K072。token、账号信息、上传会话 URL 不进日志和工具输出。内存缓存仍不能抵挡正在执行的 XSS，也不能替代前端安全。

最小 scope、个人/工作账号、AppFolder、临时上传 URL、最终条件提交均沿用既有 M06/M07 要求重新做 Web 环境验证。CORS 能过不等于 CAS 安全。缺乏可靠最终条件时保留双方和冲突副本，不能无条件覆盖；测试授权须使用专门测试账户并另获必要授权。

## 6. 能力和承诺

| 能力 | Web 首版目标 |
| --- | --- |
| 资料、关系、维护规则 | 与移动使用相同类型和兼容契约，当前未实现 |
| KDBX 编辑与导出 | GW0/GW1 通过后开放；未知库保持只读 |
| 附件 | 内存/受控预览，体积/类型限制；必要时显式导出 |
| 双云同步 | 两 provider 均需 Web 专属授权与并发证据；不保证任意部署都能连接任意 WebDAV |
| 到期提醒 | 已打开并解锁时应用内提醒；不承诺关页后提醒 |
| 系统自动填充/Passkey provider/SSH | 不支持，移动按原生能力交付，桌面系统凭据/SSH 等增强继续后续验收 |
| 系统级生物快速解锁 | 首版不提供，不用网页登录成功替代密码库解锁 |
| 离线 | 本地会话可操作；刷新后离线可用依赖可选静态包缓存，未验收不承诺 |

## 7. 独立门槛

| 门槛 | 需要的证据 | 失败处理 |
| --- | --- | --- |
| GW0 可行性 | K070–K072 + K093：浏览器真实 KDF/writer、文件/缓存/锁、双云授权和最终条件反例；固定 Chrome/Firefox/Safari 版本 | 合成只读实验；不拖低移动端安全要求；阻塞浏览器/服务明确标出 |
| GW1 数据安全 | K081/K082/K084/K085：会话、保存状态、恢复、配额、锁库与多标签、业务闭环 | 关闭相应写入/缓存/同步能力，不宣称完整 Web |
| GW2 发布 | K087/K088/K089：四原生端与 Web 往返、独立 Web 安全复核、构建交付与恢复演练 | 不允许真实主力库接入；有移动版不等于跨端完成 |

GW0 不要求把原生 OAuth 整体搬到 Web；要求经过真实浏览器验证可用路径与安全降级。GW 门槛不能取代 G0–G5；真实数据级别按 [REAL_DATA_RULES.md](REAL_DATA_RULES.md) 的新增 Web 前提执行。

研究来源 PVxx 见 [研究记录](research/personal-vault-2026-10-16.md)。
